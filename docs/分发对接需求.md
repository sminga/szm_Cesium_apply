下面这份清单可以直接交给“分发服务”负责人。核心目标是让对方提供：**接口契约、真实脱敏样例、结果资源说明、网络和证书方案、可联调环境**。只有拿到这些内容，Cesium 前端才能判断哪些结果显示在侧栏，哪些能够准确加载到地图。

**必须提供**

- [ ] **完整 API 文档**
  - 每个接口的 URL、HTTP 方法、请求参数、响应字段、必填/可选字段。
  - 字段类型、允许值、默认值、是否可能为空。
  - HTTP 状态码和错误响应格式。
  - 当前已知接口包括：
    - `GET /api/v1/receiver-profiles`
    - `POST /api/v1/identity-selections`
    - `GET /api/v1/receiver-catalog`
    - `POST /api/v1/processing-requests`
    - `GET /api/v1/processing-requests/{request_id}`
    - `GET /api/v1/products/{product_id}`
    - `GET /api/v1/datasets/{dataset_id}/content`

- [ ] **每个接口的真实脱敏 JSON 样例**
  - 不要只提供字段说明，要提供实际成功响应。
  - 同时提供至少一份失败响应。
  - 删除真实姓名、密钥、Token 等敏感信息即可，不要改变字段结构。

- [ ] **一条完整成功流程的样例**
  - 一次身份选择响应。
  - 一次目录查询响应。
  - 一次申请创建响应。
  - 同一个任务的 `pending`、`running`、`completed` 响应。
  - 完成后的 `product` 响应。
  - `product.assets` 中每个资源对应的实际测试文件。

- [ ] **任务状态定义**
  - 完整状态枚举，例如 `pending / running / completed / failed / cancelled`。
  - 每个状态是否可能回退。
  - 前端推荐轮询间隔。
  - 最长处理时间和任务保留时间。
  - 失败时错误字段、错误代码和用户可显示的信息。
  - 任务完成后 `result_product_id` 是否一定存在。

- [ ] **幂等规则**
  - `idempotency_key` 的有效期。
  - 相同键重复请求时返回原任务还是报错。
  - 相同键但参数不同如何处理。
  - 网络超时后是否允许使用同一个键重新提交。
  - 是否有键长度和字符限制。

**结果资源必须说明**

- [ ] 每个 `asset` 至少提供：
  - `dataset_id`
  - 资源名称
  - 原始文件名
  - MIME 类型，例如 `image/png`、`application/x-netcdf`
  - 文件格式，例如 `png`、`netcdf3`、`geojson`
  - 文件大小 `size_bytes`
  - 资源用途，例如 `chart`、`map_overlay`、`wind_3d`、`brief_text`
  - 创建时间或数据时刻
  - 下载地址有效期和访问条件

- [ ] **图片分类**
  - 明确哪些图片只是统计图、剖面图、时间高度图或简报图片。
  - 明确哪些图片可以叠加到 Cesium 地图。
  - 普通图表不能标记为地图影像。

- [ ] **地图影像的地理信息**
  - 坐标系，优先提供 `EPSG:4326`。
  - 覆盖范围：`west / south / east / north`。
  - 经度纬度单位是否为度。
  - 图片是否包含图例、标题、白边或坐标轴。
  - 图片是否带透明通道。
  - NoData 或透明区域如何表示。
  - 一张图跨越 180° 经线时如何表达。
  - 数据来源和必须保留的版权署名。

建议返回结构：

```json
{
  "dataset_id": "DATASET_MAP_001",
  "name": "地面风场专题图",
  "file_name": "wind_map.png",
  "content_type": "image/png",
  "format": "png",
  "data_role": "map_overlay",
  "size_bytes": 1204850,
  "crs": "EPSG:4326",
  "bounds": {
    "west": 110.2,
    "south": 38.5,
    "east": 112.8,
    "north": 40.1
  }
}
```

**NetCDF 数据必须说明**

- [ ] 是 NetCDF-3 还是 NetCDF-4/HDF5。
- [ ] 是否为原始 WRF 文件。
- [ ] 二维风场还是三维风场。
- [ ] 经度、纬度、高度和时间变量名称。
- [ ] U、V、W 变量名称、维度顺序和单位。
- [ ] 高度是海拔高度、离地高度还是模式层。
- [ ] 缺测值 `_FillValue` 和 `missing_value`。
- [ ] 经度是否跨越日期变更线。
- [ ] 单个文件最大体积和典型体积。
- [ ] 提供至少一个可用于联调的真实脱敏 NC 文件。

当前 Cesium 项目优先接受：

```text
NetCDF-3
lon(lon)
lat(lat)
lev(lev)
U(lev, lat, lon)
V(lev, lat, lon)
W(lev, lat, lon)
```

如果服务目前输出 NetCDF-4 或原始 WRF，应请对方确认能否在服务端生成符合上述约定的 NetCDF-3。公开浏览器不应依赖用户本机 Python 进行转换。
