# 资源分类、实际数据及与目标格式的差异

本机增强assets使用media_type、file_format、bbox等字段；同学建议的content_type、format、bounds不是全部同名现有字段。不要直接按建议JSON写死。

| 对方所需信息 | 当前字段/获取位置 |
|---|---|
| 资源名称与两图用途 | label、purpose；sort_order排序，asset_id标识附件 |
| 文件名/大小/类型 | file_name、size_bytes、media_type、file_format、container_format；旧版补GET dataset |
| 地理范围对象 | bbox=[west,south,east,north]，单位度；需要bounds时前端按顺序映射，不交换纬经 |
| 坐标系 | crs为用于经纬度定位的声明，source_crs_wkt独立保留原投影 |
| 时间 | 产品generated_at/valid_from/valid_until；观测时刻取metadata.source_end_utc、NC target_time_utc或数据集capture_start/end；没有给每个附件单独伪造观测时刻 |
| URL与访问 | content_url相对API路径；无签名TTL，受网络/文件可用性约束；产品到期不等于字节URL自动失效 |

data_role：chart侧栏图，brief_text文本附件，attachment/未知只下载；wind_2d/wind_3d进入相应数据加载流程但仍须检查解码器；map_overlay须有完整地理配准。纯文字简报现为summary，可无assets，不必生成图片或TXT。

## 两张真实科研图

HTTP记录12-product.json的前两项分别为“风速风向时间—高度图”和“垂直气流时间—高度图（正向上、负向下）”，文件及大小/哈希见capture-report.json。二者均chart，坐标轴、标题和图例属于科研图内容，不作地图图层。

**本次没有经过像素配准、去除坐标轴/图例的map_overlay样例。** 因此影像透明通道、NoData/透明值、影像边界像素约定、地理裁剪及跨180°的示例均不能填“已支持”。当前bbox验证要求west<east，不支持用west>east跨日期线；如未来需跨线，双方先约定分片或表达，不能靠整幅拉伸解决。普通图的bbox/crs=null准确表达不可地理贴图，不是待同学猜填。
