# 多厂商底图与坐标系适配

## 1. 目标与边界

“场景”页提供 Cesium、OpenStreetMap、天地图、高德、百度、腾讯、Google、星图和无底图。底图可以与 Sentinel-2、风场、矢量、3D Tiles 和当前高程地形同时存在，并在右侧“图层管理”中显示为一个基础底图条目。

本功能只解决二维影像底图。天地图和星图的“地形晕渲图”是带明暗效果的二维瓦片，不会产生山体高程；真正改变地表高度的 Cesium World Terrain、浏览器 DEM 和 quantized-mesh 仍在“地形”页管理。

## 2. 为什么不能直接替换 URL

Cesium 场景、风场、DEM、SHP、GeoJSON 和工具点位都以 WGS84 表达位置。国内部分地图服务使用 GCJ-02 或 BD-09，如果只把其瓦片 URL 交给普通 `UrlTemplateImageryProvider`，中国境内的影像会与 WGS84 数据产生可见偏移。

本项目采用“业务数据不变、瓦片投影适配”的边界：

| 服务 | 服务坐标/来源 | 处理方式 |
| --- | --- | --- |
| Cesium World Imagery | Cesium ion | Cesium `createWorldImageryAsync()`。 |
| OpenStreetMap | WGS84 / Web Mercator | Cesium `OpenStreetMapImageryProvider`。 |
| 天地图 | CGCS2000 | Cesium `WebMapTileServiceImageryProvider`，使用 `_w` WMTS 矩阵。 |
| 高德 | GCJ-02 | `AMapImageryProvider` 使用 `crs: "WGS84"`，在 tiling scheme 内完成对齐。 |
| 百度 | BD-09 | `BaiduImageryProvider` 使用 `crs: "WGS84"`，同时处理百度瓦片编号。 |
| 腾讯 | GCJ-02 | `TencentImageryProvider` 使用 `crs: "WGS84"`。 |
| Google | Cesium ion 资产 `3830183` | 只使用 `IonImageryProvider.fromAssetId()`，不接入非官方 Google 瓦片 URL。 |
| 星图 | 以部署者授权服务为准 | Cesium `UrlTemplateImageryProvider`；不猜测或强制修改服务坐标系。 |

CGCS2000 与 WGS84 在当前全球底图浏览尺度下不采用 GCJ-02 式纠偏。若后续接入高精度测绘成果，应以数据生产说明和控制点验证为准，不能把本模块当作测量级坐标转换工具。

## 3. 架构

### 3.1 目录与职责

- `basemapCatalog.js`：可选服务、样式、坐标说明和环境变量要求。
- `basemapProviders.js`：Provider 工厂、天地图组合规则、URL/Token 处理和生产地址保护。
- `BasemapManager.js`：多层逻辑底图的创建、原子替换、显隐、透明度和销毁。
- `layerAdapters.js`：把多个内部 `ImageryLayer` 映射成右侧一个 `basemap:current` 条目。

### 3.2 复合底图

天地图影像、矢量和地形晕渲分别使用：

```text
img_w + cia_w
vec_w + cva_w
ter_w + cta_w
```

启用境界线时在基础层与注记层之间加入 `ibo_w`。`BasemapManager` 按“基础层、境界线、注记层”的顺序插入影像栈底部。Sentinel-2 等专题影像保持在其上方，底图切换不删除这些叠加层。

### 3.3 失败与并发

每次切换都有请求版本。只有最新请求可以写入场景；旧请求晚到时被忽略。新底图的所有内部层成功加入后才移除旧底图；Provider 创建或图层加入失败时会清理本次部分结果并保留原底图。

## 4. 场景页与地形页

“场景”页按以下顺序组织：

1. 基础底图：地图服务、地图样式、天地图中文注记和境界线。
2. 专题影像：保留 Sentinel-2 作为可排序、可隐藏、可删除的影像叠加层。
3. 三维内容：保留 Cesium OSM Buildings 和高负载的 Google Photorealistic 3D Tiles。

Cesium World Terrain 已移到“地形”页。右侧“基础地形”在 World Terrain、本地 quantized-mesh 文件夹、公开目录地形和椭球之间单选；浏览器 GeoTIFF 进入独立“局部 DEM”组，可同时启用多份并覆盖基础地形。Cesium 同一时刻仍只接收一个由项目组合后的 `terrainProvider`。

## 5. Cesium ion 精简

删除了重复或容易误用为叠加层的 5 个 Google Maps 影像开关、3 个 Bing Maps 影像开关和 Earth at Night。Google Maps 卫星含标签 `3830183` 改为互斥基础底图；Sentinel-2 `3954` 继续作为专题叠加影像。

保留：

- Google Maps 卫星含标签：基础底图，资产 `3830183`。
- Sentinel-2：专题影像，资产 `3954`。
- Google Photorealistic 3D Tiles：三维内容，资产 `2275207`，默认关闭并标记高负载。
- Cesium OSM Buildings：三维内容，资产 `96188`。
- Cesium World Terrain：地形页，资产 `1`。

## 6. 配置、Vercel 与安全

配置入口见 `example/.env.example`。所有 `VITE_*` 值都随 JavaScript 发送给访客，必须使用允许浏览器公开、限制域名、限制服务范围和配额的 Token/Key。高德、百度、腾讯和星图必须由部署者提供有权使用的 HTTPS URL 模板；项目不内置或回退到依赖自带的非官方地址。

生产模式拒绝 `localhost`、`127.0.0.1` 和 `file:` 厂商瓦片地址。浏览器不会读取开发者电脑路径，也不会依赖本地 Python、Docker 或常驻服务。外部服务仍可能受 CORS、Referer 白名单、配额、区域网络和许可变化影响，失败会在场景页显示，不会静默移除当前底图。

Cesium credit 容器必须保持可见。OpenStreetMap、天地图、高德、百度、腾讯、星图、Cesium ion 和具体数据资产的最终署名要求以服务协议为准，部署者需要在上线前复核。

## 7. 依赖与许可证

新增开发依赖 `@cesium-china/cesium-map@1.0.0`，只进入示例网站构建，不改变 npm 核心库的 `dependencies`。包声明 Apache 2.0 License，发布内容包含 `LICENSE.MD`，当前安装内容约 82,276 字节，无额外运行时依赖；peer dependency `cesium ^1.118.2` 与当前安装的 `cesium 1.145.0` 满足版本范围。

采用范围仅为高德、百度和腾讯的 tiling scheme/Provider。天地图和星图继续使用 Cesium 原生 Provider。未复制第三方源码到项目，也未采用包内默认瓦片 URL。

## 8. 使用方法

1. 进入顶部“场景”。
2. 在“地图服务”选择已配置的厂商；未配置项会禁用并显示“未配置”。
3. 选择样式。天地图可额外启用中文注记和境界线。
4. 需要专题数据时打开 Sentinel-2；它会保留在底图之上，切换底图不会被删除。
5. 在右侧“底图”条目控制整组底图显隐和透明度；基础底图不可删除、不可拖动排序。
6. 需要真实高程时切换到“地形”页，而不是选择“地形晕渲图”。

- 本地桌面浏览器 `1440×900` 验证 Cesium、OSM、无底图、Google ion 切换，Sentinel-2 保留，右侧逻辑条目更新，World Terrain 启用/关闭，场景/地形页面无横向溢出，Cesium credit 可见，页面错误列表为空。

## 10. 已知限制

- 本次没有配置真实天地图、高德、百度、腾讯和星图 Token/授权 URL，因此只验证了缺少配置的禁用提示、Provider 参数和自动测试，没有验证这些厂商的真实瓦片、CORS、配额和许可。
- 真实 Vercel Preview/Production 尚未部署验证；本地生产构建不能替代线上域名白名单和跨域检查。
- 只按用户要求检查电脑端 `1440×900`，没有检查手机和平板。
- 星图服务的坐标系和 URL 结构由具体授权产品决定，部署者必须按服务文档配置并用控制点验证。
