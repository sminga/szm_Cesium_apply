# 统一场景图层管理方案（阶段 0–3）

## 目标与范围

把当前已进入 Cesium 场景的资源集中显示在右侧“图层管理”栏，允许用户查看、显隐、定位、调节透明度、移除，并在数据确实具有叠放顺序时调整顺序。地形处理/读取任务也显示在同一管理面板中，但与已加载图层分组区分。

阶段 0–3 完成本次统一管理基础能力与现有数据接入，不等同于已经实现所有未来格式。SHP、ENVI、普通 TIFF、天地图等仍需各自适配器、授权/署名核验、格式或服务验证后再接入。

## 当前分组与能力

| 分组 | 内容 | 当前操作与限制 |
| --- | --- | --- |
| 数据任务 | 浏览器 DEM 读取/处理/应用；开发者本地 DEM 转换 | 处理中可取消或移除；失败、取消后可重试。任务完成后从任务组移除，成功 DEM 以地形源出现。 |
| 底图 | 当前 Cesium/OSM/其他底图 | 保留底图切换和显示/透明度控制；不允许删除或排序，避免没有底图状态或破坏底部基准层。 |
| 影像叠加 | Cesium ion 影像 | 可显隐、改透明度、定位适用资源、移除；组内可以拖放或用排序按钮调整真实 Cesium imagery stack 顺序。 |
| 矢量数据 | 为 SHP 等格式预留 | 当前无接入适配器，不会显示空操作。需要按图层真实类型决定定位、样式和排序能力。 |
| 风场 | 二维/三维风场图层 | 可选择、显隐、定位、移除；二维风场支持固定显示高度编辑。其顺序不承诺改变三维遮挡。 |
| 3D 内容 | ion 3D Tiles | 可显隐、定位、移除。Tileset 深度测试与自身几何决定遮挡，列表顺序不会假装成为全局渲染顺序。 |
| 地形源 | 世界地形、椭球、已发布目录地形、文件夹 quantized-mesh、浏览器 GeoTIFF | 多个候选可共存于目录；单次只能有一个 `terrainProvider` 生效。切换失败时保留原活动地形。 |

## 核心结构

- `example/app/layers/layerCapabilities.js`：允许的分组、固定分组顺序和能力声明。
- `example/app/layers/SceneLayerRegistry.js`：规范化条目、校验动作、同步同组顺序、向面板发快照。
- `example/app/layers/layerAdapters.js`：把风场、底图、ion 影像、ion Tileset、地形源和任务映射成统一数据条目。
- `example/app/layers/terrainActivation.js`：串行化地形激活语义；失败或旧请求晚到时不覆盖成功活动源。
- `example/app/layers/LayerPanelController.js`：依能力显示操作，渲染分组列表、排序和设置，并保留折叠/编辑状态。
- `example/app/main.js`：应用层编排，继续由 `WindLayerManager`、`IonAssetLayerManager`、`TerrainController` 和各地形会话持有真实资源。

大致流程：

1. 资源管理器创建或加载 Cesium 资源。
2. 应用入口调用相应 adapter，将名称、来源、状态和能力登记到 `SceneLayerRegistry`。
3. 面板监听注册中心快照，只显示条目声明且能执行的操作。
4. 用户操作回到该条目的 adapter，再委托原有管理器变更 Cesium 资源。
5. 注册中心在动作成功后更新 UI；移除时先释放底层对象，成功后再删掉条目。

## 排序语义

“列表靠上”只用于支持排序的影像叠加层。Cesium 的 imagery collection 索引方向与列表阅读方向相反，`synchronizeImageryOrder()` 会倒序调用公开 `raiseToTop()`，并在渲染层实际同步后再提交新顺序。底图固定在影像底部。

不为风场、地形、3D Tiles 提供伪排序。风场粒子与 3D 几何的遮挡受深度测试、透明渲染、相机和各自 shader 影响；地形不是 imagery collection 中的栈层；多个地形不能同时成为 Cesium 当前地表。以后若加入可排序矢量/影像，要先定义真实 renderer 顺序，再声明 `reorder`。

## Cesium 官方 API 依据

- [`ImageryLayerCollection`](https://cesium.com/learn/cesiumjs/ref-doc/ImageryLayerCollection.html) 是有顺序的影像集合，公开提供 `raise()`、`raiseToTop()`、`lower()` 和 `lowerToBottom()`。因此本项目只把“拖动排序”映射到真正位于 `viewer.imageryLayers` 中的影像叠加层；`synchronizeImageryOrder()` 使用 `contains()` 检查成员后调用 `raiseToTop()`，不访问 Cesium 私有字段。
- [`Scene.imageryLayers`](https://cesium.com/learn/cesiumjs/ref-doc/Scene.html#imageryLayers) 返回 Globe 上参与渲染的 `ImageryLayerCollection`。底图与 ion 影像都处于该集合中，但本项目把底图作为固定基准层，不开放删除和排序，避免用户操作后得到无底图或含义不清的跨组顺序。
- [`Scene.terrainProvider`](https://cesium.com/learn/cesiumjs/ref-doc/Scene.html#terrainProvider) 与 [`Globe.terrainProvider`](https://cesium.com/learn/cesiumjs/ref-doc/Globe.html#terrainProvider) 都表示当前为地球表面提供几何的单个 `TerrainProvider`。因此右侧面板可以保存多个地形候选，但只能用单选方式激活其中一个，不能把多个 DEM 地形误实现为同时叠加的影像层。
- Cesium 还提供 [`Scene.setTerrain()`](https://cesium.com/learn/cesiumjs/ref-doc/Scene.html#setTerrain) 和 [`Terrain`](https://cesium.com/learn/cesiumjs/ref-doc/Terrain.html) 管理异步 Provider。当前项目继续复用已有 `TerrainController` 完成加载、错误状态、相机定位与资源接管，并在外层用请求版本控制保护“最后一次操作生效”的业务语义；没有复制 Cesium 内部实现。

本阶段没有新增第三方依赖、复制外部代码或采用新的第三方算法。外部资料只用于确认 Cesium 公开 API 的能力边界，最终实现仍以本项目测试、生产构建和桌面浏览器检查为准。

## 状态、并发与资源释放

- 地形请求只有最新请求能成为活动源。失败时目标行标为失败，已生效的源保持 active；被较新操作取代的旧 Promise 不得回写活动标识。
- Provider 已经生效但旧浏览器 DEM 会话释放失败时，仍保留新活动地形，并在该行显示清理警告，不将真实成功误报成切换失败。
- 浏览器 DEM 处理使用 AbortController 与独立任务 ID。重试创建新 ID，过期 Worker 状态回调不得修改新任务；成功后任务条目转为地形源。
- 开发者本地 DEM 转换请求支持 AbortSignal。停止浏览器等待不代表本地 CTB 子进程保证立即终止；服务端转换是否能取消仍取决于现有本地服务行为。
- 删除资源调用原拥有者清理 GPU、Provider、Worker、Service Worker 会话或网络实体；注册中心不另行保留第二份资源所有权。
- 面板订阅只拿到不含动作闭包的状态快照；能力和数据状态仍由业务管理器给出。

## Vercel 与本地文件边界

- Cesium ion Token 是浏览器可见配置，只能使用域名受限的浏览器 Token；署名区域继续可见。
- 用户从电脑选择的 GeoTIFF 或处理后地形文件夹仅在当前浏览器会话内读取，不上传、不由 Vercel 长期保存。刷新后需要重新选择。
- 在线目录/ion 资源必须使用网站可访问 URL 或 Cesium ion；本地 Python 服务只属于开发者的离线转换和目录调试路径，不是公开网站功能依赖。
- SHP、ENVI、TIFF 等“可以同时存在”需要按资源加载方式判断。举例：栅格影像可能支持透明度/顺序，SHP 需要矢量数据源与样式管理，ENVI 可能只是解析输入或多波段影像，不能共用一套未经验证的 loader。

## 使用与维护

在工作台右侧“图层管理”中按分组找到资源。眼睛图标只切换显示状态；垃圾桶会从场景移除并释放底层对象；影像层“更多设置”中调整透明度和顺序；地形组通过单选激活当前地形。处理中任务在“数据任务”组显示进度/状态，并提供取消、重试或移除。

新增图层时应遵守以下次序：确认资源生命周期所有者 -> 选择分组 -> 编写 adapter -> 只声明可验证能力 -> 注册/注销条目 -> 为动作和失败回退添加测试 -> 更新本文件与目录 README -> 完成生产构建和桌面浏览器检查。不要将文件路径、真实 Token、用户数据或服务端密钥写入条目详情。
