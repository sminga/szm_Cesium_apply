# 工具页地图标注、路线与矢量文件

## 目标与适用范围

工具页为 Cesium 示例工作台提供短期场景操作：创建/命名点位、绘制路线并让一个 GLB 模型沿路线移动、点击读取坐标，以及读取 GeoJSON/TopoJSON/Shapefile。数据和模型属于当前标签页的浏览器会话；页面不上传这些文件，也不把它们保存到服务器。

这是 `example/` 的示例网站业务能力，不属于可复用的核心风场库 `src/`。更适合临时检查、演示和浏览器内标注，不是具备保存、协作、权限或长期档案能力的 GIS 编辑器。

## 技术方案

- Cesium 官方 `ScreenSpaceEventHandler` 接收一次左键操作，控制器用互斥模式区分点、路线与坐标拾取，避免三种工具抢同一次点击。
- 点和路线使用 Cesium Entity；完整路线、点位和文件数据源都登记到既有 `SceneLayerRegistry` 的“矢量数据”组，以复用统一显隐、定位、移除和资源清理操作。
- 模型使用 Cesium `ModelGraphics`，浏览器通过 `URL.createObjectURL()` 暂时提供用户选中的单文件 GLB。路线采样由 `SampledPositionProperty` 表达，`VelocityOrientationProperty` 根据运动方向旋转模型。播放时暂时使用 Viewer 的 `Clock`，暂停、停止、自然结束或删除路线时恢复进入播放前的时钟状态。
- GeoJSON 使用原生 `GeoJsonDataSource.load()`。TopoJSON 不被当成 GeoJSON 直接加载；`vectorFileLoader.js` 按 TopoJSON 的 delta 编码、仿射变换、共享弧线和反向弧线索引转换为 FeatureCollection，再交给 Cesium。
- Shapefile 使用 npm package `shpjs@6.2.0`，在浏览器本地读取 ZIP 或同名 `.shp/.dbf/.prj/.cpg` 文件组，再统一转换为 FeatureCollection。该依赖为 MIT License，本项目只调用公开 API，不复制其源码。

## 使用方式

### 创建并命名点位

1. 顶部打开“工具”，选择“创建点”。
2. 点击地图空白位置添加点。工具保持激活，可连续创建多个点；点击一个已有标记可选中它。
3. 在“点位标注”中编辑名称并保存。点位可在右侧场景图层中显隐、定位或移除。
4. 点击“退出地图操作”或按 `Escape` 结束创建模式。

### 绘制模型路线

1. 选择“绘制路线”，按移动顺序逐点点击地图，至少添加两个位置。
2. 点击“结束路线”，在路线名称栏填写并保存名称。
3. 选择路线后加载单文件 `.glb`；通过速度输入框设定米/秒，再点击“播放”。
4. 使用暂停、继续或停止管理播放。路线到达末点后自动结束并恢复原 Viewer 时钟。
5. 移除路线会同时移除它的 GLB Entity，并撤销临时 Object URL。

路线位置按照可获得的场景表面、地形射线或椭球拾取高度记录。移动速度按相邻路径点的三维直线距离估计；当前没有贴地路径重采样、道路跟随、碰撞或曲线平滑。

### 获取坐标

选择“点击获取坐标”后点击地图。结果以 WGS84 十进制度显示经度、纬度、高度和高度来源，拾取优先级为场景深度、地形表面、椭球。深度拾取失败时会自动回退；椭球高度并不等于真实地形高程。

### 加载矢量文件

点击“选择并加载矢量文件”，可以选择 `.geojson`、`.json`、一个 Shapefile `.zip`，或同时选择同名的 `.shp/.dbf/.prj/.cpg` 配套文件。成功后资源进入右侧“矢量数据”分组，可显隐、定位和移除。TopoJSON 的多个 `objects` 会合并成 FeatureCollection，并在各要素属性中增加 `topologyObject` 以保留对象来源；多个 Shapefile 结果也会合并为一个 FeatureCollection。

示例：

```js
import { loadVectorFile } from "../services/vectorFileLoader.js";

const { geojson, format, featureCount } = await loadVectorFile(file);
const dataSource = await Cesium.GeoJsonDataSource.load(geojson, { clampToGround: true });
viewer.dataSources.add(dataSource);

// Shapefile ZIP 或配套文件组使用同一个入口，文件不会上传。
const fileList = [shpFile, dbfFile, prjFile];
const shapefile = await loadVectorFile(fileList);
```

## 文件与数据边界

- 单次 GeoJSON/TopoJSON/Shapefile 文件选择总大小最多 50 MiB，最多 100,000 个要素；GLB 最多 100 MiB。超过限制会在工具页显示原因。限制用于降低浏览器解析和内存风险，不代表设备都能顺畅处理接近上限的数据。
- 只支持 `.glb` 单文件模型。`.gltf` 引用的外部纹理/二进制文件、本地矢量目录、服务端上传、持久化保存和导出当前都不支持。
- Shapefile 建议选择包含 `.shp`、`.dbf`、`.prj` 等配套文件的 ZIP；单独 `.dbf`、`.prj` 或 `.shx` 文件不能独立解析。缺少 `.dbf` 可能没有属性字段，缺少 `.prj` 时无法根据投影信息转换。
- 访客文件通过浏览器 File API 读取，GLB 仅通过临时 Blob URL 提供给 Cesium；页面不会向 Vercel、开发者本地 Python 服务或第三方发送文件内容。
- 刷新/关闭标签页后清除点、路线、已加载文件、模型和名称。需要长期留存的公开数据应由维护者发布为公开静态资源或对象存储对象，本工具不替代发布流程。
- GLB 具体尺寸、节点朝向与资源复杂度会影响模型外观和性能。超大/复杂文件、老旧设备和 WebGL 不可用时不能保证加载成功；错误会在工具状态区域显示。

## 代码入口与生命周期

| 文件 | 职责 |
| --- | --- |
| `example/app/sceneToolsController.js` | 互斥地图模式、点/路线/模型 Entity、拾取、时钟备份恢复、工具表单和资源释放。 |
| `example/services/vectorFileLoader.js` | 本地 JSON/Shapefile 读取、文件/要素限制、TopoJSON 和 Shapefile 到 GeoJSON 转换。 |
| `example/index.html` | 工具面板字段、按钮、文件选择和状态输出。 |
| `example/app/main.js` | 创建控制器、传递现有图层注册中心，并在页面卸载前销毁。 |
| `example/ui/index.css` | 地图操作模式、名称/速度输入、状态和坐标结果样式。 |
| `tests/example/sceneToolsController.test.js` | 坐标格式、拾取回退和路线速度采样测试。 |
| `tests/example/vectorFileLoader.test.js` | GeoJSON/TopoJSON/Shapefile 解析、变换、弧线合并/反向索引和限制测试。 |

删除/关闭控制器时会释放 ScreenSpaceEventHandler 和 DOM 监听，移除 Entity/DataSource、停止活动路线并还原 Viewer 时钟，撤销所有 Blob URL。矢量加载异步完成时还会检查页面控制器是否已销毁，避免迟到数据重新进入场景。

## Vercel、验证与限制

本站是 Vite 静态构建，无新增 Serverless Function、路由、环境变量或部署资源。Vercel 部署的访客使用相同的浏览器代码，且不依赖固定盘符、localhost 或本机服务。此文档和本地构建不证明某个线上域名已经部署；Preview/Production 仍须实际访问验证。

自动检查：

```powershell
npm test -- --run tests/example/vectorFileLoader.test.js tests/example/sceneToolsController.test.js
npm run build:vercel
```

本轮已通过 `npm test`（17 个测试文件、85 项测试）和 `npm run build:vercel`；新增 Shapefile 解析单测覆盖 ZIP、同名配套文件组和缺少 `.shp` 的错误，场景工具定向测试在修复 FileList 生命周期后为 6 项通过。最终入口 bundle 约 303.95 kB、gzip 97.81 kB。在本机 Vite 生产预览的桌面浏览器中，使用用户提供的 `D:\下载\内蒙古自治区` 文件组临时副本完成真实导入：页面显示 12 个 Polygon 要素，右侧“矢量数据”组登记图层并提供隐藏、定位、移除动作；原始文件的 Node 解析结果同样为 12 个要素、WGS84 坐标和行政区属性字段。当前已验证的是该 WGS84 Polygon 样本，其他投影、复杂 MultiPolygon、超大文件、真实 GLB 播放周期、在线地形拾取差异、Vercel Preview/Production 仍未验证。
