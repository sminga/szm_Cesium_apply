# 2026-09-22：二维/三维多风场、本地目录和 DEM 地形

### 多风场图层-

- 新增 `WindLayer2D`。二维文件读取 U/V 后自动把 W 设为 0，并固定在用户指定的绝对高度。
- 新增 `WindLayerManager`，允许一个 Cesium Viewer 同时显示多个二维风场和多个三维风场。
- 二维风场目录支持多选文件，使用“起始高度 + 层间距”自动把多个文件放置到不同高度。
- 风场图层列表支持选择当前层、显隐、定位和删除。
- 每个二维图层可以在图层列表中单独修改显示高度。

### 三维高度控制

- 增加“全部高度”模式，显示文件内完整三维高度范围。
- 增加“连续范围”模式，用户可以填写最低和最高显示高度。
- 增加“离散单层”模式，从 NetCDF 的真实高度层中选择一个高度。
- 高度限制同时作用于初始粒子播种、粒子越界重生、GPU 垂直运动和最终绘制，不是仅在界面上隐藏。
- 对非等距高度层增加分段归一化，避免直接按最高/最低高度线性换算造成采样层偏移。

### 默认风场目录

- 浏览器不能强制系统文件对话框第一次打开任意 Windows 绝对路径，因此改为网页内置文件目录。
- 本地服务新增 `/api/wind-files`，默认列出 `tools/converted` 中的 `.nc` 和 `.cdf` 文件。
- 本地服务新增 `/files/wind/...`，网页可直接读取目录中的文件。
- 加载按钮优先打开项目文件目录，同时保留“浏览其他位置”作为备用入口。

### 本地 DEM 与 quantized-mesh

- 参考 `cesium-terrain-builder-docker`，新增 `tools/terrain/build_quantized_mesh.py`。
- 处理流程为 GDAL 重投影到 EPSG:4326，然后使用 CTB 生成 Mesh 瓦片和 `layer.json`。
- 默认 Docker 镜像为 `tumgis/ctb-quantized-mesh:latest`，可通过服务参数替换。
- 本地服务新增 DEM 上传处理接口、地形目录接口和静态瓦片托管。
- 前端新增“选择并处理 DEM”“刷新地形列表”“加载地形”和“恢复椭球地形”按钮。
- 前端使用 `CesiumTerrainProvider.fromUrl()` 加载标准 quantized-mesh，生成结果可供其他 Cesium 项目使用。
- 当前开发机器没有安装 Docker，因此已验证错误提示路径，但未在本机实际生成 DEM 瓦片。

### 使用
注释 1

要完成“本地 DEM 转换为 Cesium 可加载的 quantized-mesh 地形”，需要在 Windows 上安装并运行 Docker Desktop，然后让项目中的脚本通过 Docker 调用 `tumgis/ctb-quantized-mesh:latest` 镜像进行转换。具体步骤如下。

## 1. 安装 Docker Desktop

在 Windows 上安装完整的 **Docker Desktop**，不要只安装 Docker 命令行工具。

安装时建议选择：

- 使用 **WSL 2 backend**
- 启用 Windows Subsystem for Linux
- 启用 Virtual Machine Platform

如果电脑没有 WSL 2，可以用管理员 PowerShell 执行：

```powershell
wsl --install
```

然后重启电脑。

启动 Windows 后，打开 Docker Desktop，等待界面显示 Docker 已经运行。Docker Desktop 必须保持打开，后续脚本才能调用 Docker。

## 2. 检查 Docker 是否可用

打开 PowerShell，执行：

```powershell
docker --version
```

正常情况下会看到类似：

```text
Docker version 27.x.x
```

然后执行：

```powershell
docker info
```

如果 Docker 正常运行，会显示服务器、容器、镜像等信息。

如果出现下面这类错误：

```text
error during connect
Cannot connect to the Docker daemon
```

说明 Docker Desktop 没有启动完成。需要先打开 Docker Desktop，并等待它完全启动后再执行命令。

注意：仅仅看到 `docker --version` 有输出还不够，必须确保 `docker info` 也能够正常执行，因为真正进行 DEM 转换的是 Docker daemon。

## 3. 拉取 DEM 转换镜像

第一次使用前，在 PowerShell 中执行：

```powershell
docker pull tumgis/ctb-quantized-mesh:latest
```

这个命令会下载项目默认使用的镜像。

下载完成后，可以用下面的命令检查镜像是否存在：

```powershell
docker images
```

列表中应该能看到：

```text
tumgis/ctb-quantized-mesh
```

如果下载失败，常见原因包括：

- Docker Desktop 没有启动
- 网络无法访问 Docker Hub
- 公司网络或校园网络设置了代理
- Docker Desktop 的代理没有配置正确
- 磁盘空间不足

可以先测试 Docker 是否能运行普通容器：

```powershell
docker run --rm hello-world
```

如果 `hello-world` 也运行失败，说明 Docker 本身还没有配置好，不是项目脚本的问题。

## 4. 启动项目的本地服务

进入项目目录：

```powershell
cd "D:\AAAcode\CesiumLearn\Cesium-learn\Cesium-Learn\OtherPeopleS\cesium-wind-layer-3d"
```

启动本地服务：

```powershell

```

正常情况下会启动：


这个服务主要负责：

- 调用 Python DEM 处理脚本

- 托管转换后的 `.terrain` 文件
- 提供本地地形列表
- 提供本地风场文件列表

这个 PowerShell 窗口需要保持运行，不要关闭。

## 5. 启动前端页面

再打开一个新的 PowerShell 窗口，同样进入项目目录：

```powershell
cd "D:\AAAcode\CesiumLearn\Cesium-learn\Cesium-Learn\OtherPeopleS\cesium-wind-layer-3d"
```

启动 Vite 前端：

```powershell
npm run dev
```

浏览器打开：

```text
http://localhost:3000/
```

不能直接双击 HTML 文件打开，因为浏览器的 `file://` 模式无法正确访问本地地形瓦片和服务接口。

## 6. 通过 GUI 处理 DEM

打开网页后，进入本地地形相关工具区域。

点击类似以下名称的按钮：

```text
选择并处理 DEM
```

然后选择本地 DEM 文件。

当前脚本支持的输入格式为：

```text
.tif
.tiff
.img
.asc
.dem
```

例如：

```text
D:\data\sample_dem.tif
```

选择文件后，网页会把文件发送给本地服务，服务再调用：

```text
tools\terrain\build_quantized_mesh.py
```

脚本会自动执行以下操作：

1. 将原始 DEM 临时复制到：

```text
tools\terrain-input\
```

2. 使用 Docker 中的 `gdalwarp` 将数据转换到 EPSG:4326。

3. 使用 `ctb-tile` 生成 Cesium quantized-mesh 地形瓦片。

4. 将结果保存到：

```text
tools\terrain-output\<数据集名称>\
```

5. 检查输出目录中是否存在：

```text
layer.json
```

6. 删除临时输入文件和中间 GeoTIFF 文件。

处理成功后，网页应提示类似：

```text
DEM 处理成功
输出目录：tools/terrain-output/sample_dem/
```

实际的绝对路径通常类似：

```text
D:\AAAcode\CesiumLearn\Cesium-learn\Cesium-Learn\OtherPeopleS\cesium-wind-layer-3d\tools\terrain-output\sample_dem\
```

## 7. 检查是否转换成功

处理完成后，打开输出目录：

```powershell
explorer ".\tools\terrain-output"
```

进入对应的数据集目录，例如：

```text
tools\terrain-output\sample_dem\
```

至少应检查以下文件：

```text
layer.json
```

以及若干 `.terrain` 瓦片文件。

可以用 PowerShell 检查：

```powershell
Test-Path ".\tools\terrain-output\sample_dem\layer.json"
```

如果返回：

```text
True
```

说明基本输出结构已经生成。

也可以查看目录内容：

```powershell
Get-ChildItem ".\tools\terrain-output\sample_dem" -Recurse
```

如果目录中只有日志或空目录，没有 `layer.json` 和 `.terrain` 文件，说明处理失败，需要查看本地服务窗口中的错误信息。

## 8. 在 Cesium 中加载处理后的地形

DEM 处理成功后，回到网页 GUI：

1. 点击刷新本地地形列表。
2. 选择刚才生成的地形数据集。
3. 点击加载本地地形。
4. Cesium 应该切换到对应的本地 quantized-mesh 地形。

本地地形一般通过以下地址访问：

```text
http://127.0.0.1:8765/terrain/<数据集名称>/
```

网页不能直接从 Windows 文件夹读取 `.terrain` 文件，必须通过 `local_service.py` 提供 HTTP 服务。

## 9. 命令行备用方式

如果 GUI 暂时不能使用，也可以直接通过命令行处理 DEM。

在项目根目录执行：

```powershell
py tools/terrain/build_quantized_mesh.py "D:\data\dem.tif"
```

例如：

```powershell
py tools/terrain/build_quantized_mesh.py "D:\AAAcode\data\mountain.tif"
```

处理成功后，输出目录默认位于：

```text
tools\terrain-output\mountain\
```

然后启动本地服务：

```powershell
npm run local:server
```

再在网页中刷新地形列表并加载。

## 10. DEM 文件准备要求

为了提高成功率，建议注意以下事项：

- DEM 最好是单个文件。
- DEM 应该带有正确的坐标参考系 CRS。
- 如果没有 CRS，脚本可能无法正确判断地理位置。
- 数据最好是 GeoTIFF 格式，即 `.tif` 或 `.tiff`。
- 多个 DEM 瓦片需要先拼接，或者逐个处理。
- DEM 范围越大、分辨率越高，处理时间越长。
- 文件路径尽量使用英文、数字和下划线，避免特殊符号。
- 输出目录所在磁盘需要有足够空间。
- Docker Desktop 需要保持运行到处理完成。

## 11. 常见错误

### 错误一：找不到 Docker

如果看到：

```text
docker command not found
```

或者：

```text
无法将“docker”项识别为 cmdlet
```

说明 Docker Desktop 没有安装，或者 Docker 没有加入 PATH。

解决方法：

1. 安装 Docker Desktop。
2. 重启 PowerShell。
3. 再执行：

```powershell
docker --version
```

### 错误二：Docker daemon 未运行

如果看到：

```text
Cannot connect to the Docker daemon
```

解决方法：

1. 打开 Docker Desktop。
2. 等待状态变为 Running。
3. 执行：

```powershell
docker info
```

### 错误三：镜像下载失败

执行：

```powershell
docker pull tumgis/ctb-quantized-mesh:latest
```

如果失败，可以检查：

```powershell
docker run --rm hello-world
```

如果网络问题持续存在，需要在 Docker Desktop 的设置中配置代理，或者换用可以访问 Docker Hub 的网络环境。

### 错误四：提示缺少 `layer.json`

这通常说明转换过程没有完整执行，可能原因包括：

- 输入 DEM 无法读取
- DEM 坐标系缺失或错误
- Docker 镜像执行失败
- CTB 工具处理失败
- 磁盘空间不足
- DEM 文件损坏

需要查看运行 `npm run local:server` 的 PowerShell 窗口，里面会有具体错误日志。

### 错误五：网页能打开，但地形加载失败

检查以下内容：

```powershell
npm run local:server
```

是否仍在运行。

然后访问：

```text
http://127.0.0.1:8765/health
```

如果返回健康状态，说明本地服务正常。

还需要确认：

```text
tools/terrain-output/<名称>/layer.json
```

确实存在，并且浏览器访问的是：

```text
http://localhost:3000/
```

而不是直接双击 HTML 文件。
