## 2026-10-18：场景页新增 Cesium ion 公共资产开关并清理工具页说明

### 更新背景

- 用户要求删除“工具”页中的“功能入口已归类”和“服务状态”两段说明文字。
- 原“场景”页只能切换默认 Cesium 影像、OSM 建筑物和世界地形，无法直接选择 Cesium ion 公共资产列表中的 Google Maps、Bing Maps、Sentinel-2、Earth at Night 和 Google Photorealistic 3D Tiles。
- 公共影像、3D Tiles 和底图属于不同的 Cesium 生命周期；如果继续使用原来的 `imageryLayers.removeAll()` 切换底图，会误删用户已经打开的公共影像，并造成开关状态与地图不一致。

### 修改内容

- 删除“工具”页两段说明内容，保留顶部“工具”页签和空页面容器，不改变现有四页签导航结构。
- 在“场景”页新增 10 个公共影像开关：Google Maps 等高线、仅标签、道路、卫星含标签、卫星，Sentinel-2、Earth at Night，以及 Bing Maps 道路、航空含标签、航空。
- 在同页新增 Google Photorealistic 3D Tiles 开关，并保留 Cesium OSM Buildings 和 Cesium World Terrain 开关；界面显示截图对应的 ion 资产 ID。
- 新增 `IonAssetLayerManager`，分别管理 ion 影像和 3D Tiles 的异步加载、关闭、取消竞态和页面卸载清理。
- 底图切换改为只替换影像栈最底层的底图，不再清空全部影像；已开启的 ion 公共影像在切换 Cesium 影像、OpenStreetMap 或无底图时保持不变。
- 右侧场景状态新增 ion 影像数量，并把原“建筑物”状态扩展为 3D Tiles 数量。
- 未配置 `VITE_CESIUM_ION_TOKEN` 时禁用全部 ion 公共资产和世界地形开关，并在页面显示明确原因；不向访客电脑的 `localhost` 发起请求。
- 恢复 Cesium credit 容器显示，确保 Bing、Google、Sentinel、OpenStreetMap 和 Cesium ion 数据提供者的署名可以在地图右下角显示。
- 新增专题文档 `docs/Cesium ion公共资产开关.md`，集中记录资产 ID、生命周期、Vercel 配置、常见错误、验证方法和源码学习顺序。

### 实现说明

- 公共影像使用 `Cesium.IonImageryProvider.fromAssetId()` 加载，加入底图之上的影像栈；关闭时从 `ImageryLayerCollection` 移除并销毁对应图层。
- 3D Tiles 使用 `Cesium.Cesium3DTileset.fromIonAssetId()` 加载。关闭开关时从 `PrimitiveCollection` 移除并释放资源，避免高精度城市模型继续占用 GPU 内存。
- 每个资产都有独立请求版本号。若用户在网络请求完成前关闭开关，晚到的成功结果不会重新插入场景，晚到的失败也不会覆盖已经显示的“已关闭”状态。
- Google Photorealistic 3D Tiles 使用 `maximumScreenSpaceError: 24`、`cacheBytes: 256 MiB` 和 `maximumCacheOverflowBytes: 128 MiB`，在保持可用画质的同时限制公开网站的客户端缓存和显存压力。
- 公共资产共 13 项：10 个影像、2 个 3D Tiles 和 1 个地形。影像和 3D Tiles 可以独立组合；高程地形仍由 `TerrainController` 保证同一时间只有一个地形提供者生效。

### Vercel 部署说明

- 本次仍是 Vite 静态站点，没有新增 Serverless Function、固定域名、后端密钥、本地绝对路径或生产环境 `localhost` 依赖。
- `VITE_CESIUM_ION_TOKEN` 会进入浏览器构建产物，只能使用允许公开到浏览器且已限制 Vercel 预览域名、生产域名和本地域名的 Token，不能放置私密服务端密钥。
- 公共资产的数据由访问者浏览器直接向 Cesium ion 及其数据提供方请求，会增加网络流量、GPU 内存和渲染负载；Google Photorealistic 3D Tiles 尤其适合按需开启，不应默认加载。
- Vercel 实际预览域名和生产域名尚未部署验证；仍需在线确认 Token 域名限制、第三方数据可达性、署名显示、缓存和真实带宽表现。

### 用户使用方法

1. 打开顶部“场景”页，在“公共影像”中打开需要的影像；多个开关可以同时启用，后打开的影像位于更上层。
2. 在“三维与地形”中按需打开 Google Photorealistic 3D Tiles、Cesium OSM Buildings 或 Cesium World Terrain。
3. 切换底图不会关闭公共影像；需要释放网络和 GPU 资源时，直接关闭对应资产开关。
4. 若所有开关为禁用状态并提示未配置 Token，需要部署维护者在 Vercel 配置 `VITE_CESIUM_ION_TOKEN` 后重新构建，而不是让普通访客输入 Token。

## 2026-10-18：建立按功能职责管理文件与目录的规范

### 实现说明

- “选择并处理 NC”只负责把原始 NetCDF 交给开发者本机 Python 服务转换；转换完成后，风场数据的加载和渲染仍在同一个“风场”页继续操作。
- “选择并处理 DEM”只负责通过开发者本地服务和 Docker CTB 生成 quantized-mesh；处理结果可以通过下方“加载本地文件夹”立即检查，也可以发布到公开地形目录或对象存储。
- “加载本地文件夹”调用浏览器文件夹选择器，检查 `layer.json` 和 `.terrain` 瓦片，并通过 Service Worker 的同源虚拟 URL 交给 Cesium。文件只在当前浏览器会话中读取，不会上传到 Vercel、项目服务器或第三方服务。
- “刷新地形目录”重新读取随网站发布的目录，并在开发环境合并本地服务目录；“选择目录地形”使用弹窗浏览目录；“应用所选地形”加载当前下拉框选中的 URL。三个按钮处理的是目录数据，不会扫描电脑任意文件夹。
- 新增 `syncTerrainActions()`：当地形下拉框没有有效 URL 时禁用“应用所选地形”；“定位当前地形”继续由地形状态订阅逻辑控制，只在当前本地地形存在有效 `bounds` 时启用。
- 目录刷新会重建下拉框。为避免刷新后丢失仍在使用的浏览器本地地形选项，`refreshTerrains()` 会重新插入当前 `localTerrainSession`，再尝试恢复刷新前的选中项。
- 释放浏览器本地地形会话时同步移除对应选项并更新按钮状态，避免页面仍显示可应用但 URL 已失效的地形。
- `local-terrain-sw.js` 增加关键中文注释，说明会话只保存规范化路径、只拦截 `/__local-terrain__/`、Service Worker 重启后向页面取回 `File`，以及 gzip 瓦片的解压兼容逻辑。

## 2026-10-15：降低风场流动速度的可调下限

- 调整 `src/terrain/TerrainController.js`，只有控制器处于 `ready` 状态时，瓦片进度和运行时瓦片错误才会更新最后成功地形快照。

- 新增连续失败回归测试，覆盖“成功加载本地地形、第一次加载失败、旧地形继续产生进度和错误事件、第二次加载再次失败”的完整顺序。

```powershell
wsl --install
```

然后重启电脑。

启动 Windows 后，打开 Docker Desktop，等待界面显示 Docker 已经运行。Docker Desktop 必须保持打开，后续脚本才能调用 Docker。

## 2. 检查 Docker 是否可用

打开 PowerShell，执行：

```powershell
docker --version
```

正常情况下会看到类似：

```text
Docker version 27.x.x
```

然后执行：

```powershell
docker info
```

如果 Docker 正常运行，会显示服务器、容器、镜像等信息。

如果出现下面这类错误：

```text
error during connect
Cannot connect to the Docker daemon
```

说明 Docker Desktop 没有启动完成。需要先打开 Docker Desktop，并等待它完全启动后再执行命令。

注意：仅仅看到 `docker --version` 有输出还不够，必须确保 `docker info` 也能够正常执行，因为真正进行 DEM 转换的是 Docker daemon。

第一次使用前，在 PowerShell 中执行：

下载完成后，可以用下面的命令检查镜像是否存在：

```powershell
docker images
```

列表中应该能看到：

```text
tumgis/ctb-quantized-mesh
```

如果下载失败，常见原因包括：

- Docker Desktop 没有启动
- 网络无法访问 Docker Hub
- 公司网络或校园网络设置了代理
- Docker Desktop 的代理没有配置正确
- 磁盘空间不足

可以先测试 Docker 是否能运行普通容器：

```powershell
docker run --rm hello-world
```

如果 `hello-world` 也运行失败，说明 Docker 本身还没有配置好，不是项目脚本的问题。

网页不能直接从 Windows 文件夹读取 `.terrain` 文件，必须通过 `local_service.py` 提供 HTTP 服务。

## 9. 命令行备用方式

如果 GUI 暂时不能使用，也可以直接通过命令行处理 DEM。

在项目根目录执行：

```powershell
py tools/terrain/build_quantized_mesh.py "D:\data\dem.tif"
```

例如：

```powershell
py tools/terrain/build_quantized_mesh.py "D:\AAAcode\data\mountain.tif"
```

处理成功后，输出目录默认位于：

```text
tools\terrain-output\mountain\
```

然后启动本地服务：

```powershell
npm run local:server
```

再在网页中刷新地形列表并加载。

## 10. DEM 文件准备要求

为了提高成功率，建议注意以下事项：

- DEM 最好是单个文件。
- DEM 应该带有正确的坐标参考系 CRS。
- 如果没有 CRS，脚本可能无法正确判断地理位置。
- 数据最好是 GeoTIFF 格式，即 `.tif` 或 `.tiff`。
- 多个 DEM 瓦片需要先拼接，或者逐个处理。
- DEM 范围越大、分辨率越高，处理时间越长。
- 文件路径尽量使用英文、数字和下划线，避免特殊符号。
- 输出目录所在磁盘需要有足够空间。
- Docker Desktop 需要保持运行到处理完成。

## 11. 常见错误

### 错误一：找不到 Docker

如果看到：

```text
docker command not found
```

或者：

```text
无法将“docker”项识别为 cmdlet
```

说明 Docker Desktop 没有安装，或者 Docker 没有加入 PATH。

解决方法：

1. 安装 Docker Desktop。
2. 重启 PowerShell。
3. 再执行：

```powershell
docker --version
```

### 错误二：Docker daemon 未运行

如果看到：

```text
Cannot connect to the Docker daemon
```

解决方法：

1. 打开 Docker Desktop。
2. 等待状态变为 Running。
3. 执行：

```powershell
docker info
```

### 错误三：镜像下载失败

执行：

```powershell
docker pull tumgis/ctb-quantized-mesh:latest
```

如果失败，可以检查：

```powershell
docker run --rm hello-world
```

如果网络问题持续存在，需要在 Docker Desktop 的设置中配置代理，或者换用可以访问 Docker Hub 的网络环境。

### 错误四：提示缺少 `layer.json`

这通常说明转换过程没有完整执行，可能原因包括：

- 输入 DEM 无法读取
- DEM 坐标系缺失或错误
- Docker 镜像执行失败
- CTB 工具处理失败
- 磁盘空间不足
- DEM 文件损坏

需要查看运行 `npm run local:server` 的 PowerShell 窗口，里面会有具体错误日志。

### 错误五：网页能打开，但地形加载失败

检查以下内容：

```powershell
npm run local:server
```

是否仍在运行。

然后访问：

```text
http://127.0.0.1:8765/health
```

如果返回健康状态，说明本地服务正常。

还需要确认：

```text
tools/terrain-output/<名称>/layer.json
```

确实存在，并且浏览器访问的是：

```text
http://localhost:3000/
```

而不是直接双击 HTML 文件。
