## 2026-10-15：降低风场流动速度的可调下限

### 更新背景

- 工作台“风场”页面中的“流动速度”滑块原来最低只能调到 `0.1`。该值会直接作为 `speedFactor` 参与 GPU 粒子位移计算，在需要观察缓慢流动、局部转向或短时间步轨迹时仍然过快。
- 本次修改只降低用户界面的可调下限，不改变默认展示速度，避免现有用户打开页面后看到与之前明显不同的动画节奏。

### 修改内容

- 将 `example/index.html` 中“流动速度”滑块的最小值从 `0.1` 降为 `0.01`。
- 将滑块步进从 `0.1` 降为 `0.01`，使用户能够选择 `0.01`、`0.02`、`0.03` 等更细的慢速档位。
- 保持滑块最大值 `5`、初始值 `0.3` 和 `sharedOptions.speedFactor` 默认值 `0.3` 不变。
- 更新 `example/README.md`，明确新的速度范围、步进和默认值。

### 实现说明

- 滑块输入仍由 `bindRange("speed", "speedFactor")` 处理。用户拖动后，数值会写入共享选项，并通过 `updateAllLayers()` 同步到所有已加载的二维和三维风场。
- 渲染计算继续使用 `(pixelSize + 50) * speedFactor` 生成速度缩放因子。新的最小值 `0.01` 约为旧最小值 `0.1` 的十分之一，因此最低档粒子位移也约为原来的十分之一。
- 渲染代码没有额外的 `speedFactor` 下限钳制，因此不需要修改着色器、`WindLayer3D`、`WindLayer2D` 或 npm 包公开类型。

### Vercel 部署说明

- 本次只修改随 Vite 构建发布的静态 HTML 控件属性和中文文档，不新增 API、路由、Serverless Function、环境变量、依赖或外部资源。
- `npm run build:vercel` 会把新的滑块范围写入 `site-dist`，预览域名和生产域名使用相同行为。
- 本次修改不增加部署包体积，不改变 Cesium 静态资源、示例风场、公开地形目录、缓存或跨域策略。

### 用户使用方法

1. 打开工作台并进入顶部“风场”模式。
2. 在左侧“渲染参数”中找到“流动速度”。
3. 将滑块向左移动；最低可以设置为 `0.01`，显示值会以 `0.01` 为步进变化。
4. 修改会立即应用到当前所有风场图层，新加载的风场也会继续使用最后设置的共享速度。

### 兼容性与影响范围

- 默认值仍是 `0.3`，未主动调节滑块的用户不会受到影响。
- `WindLayerOptions.speedFactor` 的名称、类型和程序调用方式保持不变；通过代码直接传入速度的现有项目无需迁移。
- 二维和三维风场共用这一控制项，调节时两类已加载图层都会同步变化。
- 本地开发页面和 Vercel 公开站点使用同一份控件标记，功能行为一致。

### 验证过程与结果

- 已执行静态一致性检查：页面中的速度控件为 `min="0.01"`、`step="0.01"`、`value="0.3"`，并确认 `sharedOptions.speedFactor` 仍为 `0.3`。
- 已执行 `node --check example/app/main.js` 和本次涉及文件的 `git diff --check`，均通过。
- 已执行完整 `npm test`：6 个 JavaScript 测试文件、27 项测试全部通过。
- 已执行 `npm run build`：npm 库的 ES/CJS 产物和发布包目录生成成功；仍存在原有的 named/default export 混用警告，但不影响构建结果，且与本次速度滑块调整无关。
- 已执行 `npm run build:vercel`：Vercel 等价站点生产构建成功，`site-dist/index.html`、页面 CSS/JS、Cesium 静态资源和示例风场资产均正常生成。
- 已检查 `site-dist/index.html`，确认生产页面保留 `min="0.01"`、`step="0.01"` 和默认 `value="0.3"`。

### 已知限制与后续事项

- 粒子视觉速度还会受到相机像素尺寸和帧率调整影响，因此不同缩放级别和设备上的主观速度可能略有差异。

## 2026-10-12：建立公开地形目录与 Vercel 站点构建边界

### 更新背景

- 示例入口原来直接导入被 Git 忽略的 `example/config/serviceTokens.js`，并从同样被忽略的 `dist` 读取库代码。干净克隆或 Vercel 构建无法保证这两个文件存在。
- 页面默认调用 `http://127.0.0.1:8765` 读取地形和执行 Python/Docker 转换。部署为公开网站后，这个地址指向访问者自己的电脑，既不能提供线上功能，也会产生误导和无效网络请求。
- 本地 DEM 处理结果只保存在 `tools/terrain-output`，缺少一种随网站部署或指向对象存储的公开地形发现机制。

### 修改内容

- 新增 `example/services/terrainCatalogClient.js`，默认读取 `example/public/terrain/catalog.json`，将目录项中的相对 URL 基于目录响应地址解析，并按 URL 合并可选的开发者本地目录。
- 新增空的公开目录和发布说明。小型 quantized-mesh 数据可以随 Vite 静态构建发布；大型数据建议使用对象存储或 CDN，并在目录中填写绝对 HTTPS URL。
- 示例入口改为直接从 `src/index.js` 引入项目模块，不再要求先生成 `dist`；Cesium ion Token 改由 `VITE_CESIUM_ION_TOKEN` 提供，不再依赖被忽略的 JavaScript 配置文件。
- Cesium Viewer 不再隐式创建 ion 默认底图。没有 Token 时页面默认加载 OpenStreetMap；有 Token 时仍可使用 Cesium 影像、OSM 建筑物和 Cesium World Terrain。
- 恢复 Cesium credit 容器显示，并调整到地图右下角，确保 OpenStreetMap、Cesium ion 和其他影像/地形提供者的署名不会被公开页面隐藏。
- 本地 Python/Docker 工具只在 Vite 开发模式或显式设置 `VITE_ENABLE_LOCAL_TOOLS=true` 时启用。公开生产构建不探测 localhost，并禁用 NetCDF、DEM 转换按钮，向普通用户说明这是开发者离线流程。
- 新增 `vite.example.config.js`、`vercel.json`、`.vercelignore`、`build:site` 和 `build:vercel`，将公开工作台独立构建到 `site-dist`，同时保留原 `npm run build` 的 npm 库构建职责。
- 示例风场 URL 改为通过 `new URL(..., import.meta.url)` 交给 Vite 追踪，确保 `wind_3d.json` 被复制到带哈希的生产资源目录，而不是只在开发服务器中可见。
- 新增 `docs/公开地形与Vercel部署.md`，说明目录格式、离线预处理、对象存储、环境变量、Vercel 构建和发布验证流程。

### 实现说明

- `catalog.json` 每个有效条目至少包含 `name` 和 `url`，还可包含 `bounds`、层级、瓦片数量、数据大小、法线、水面遮罩和描述等元数据。
- 页面始终先读取公开目录。开发模式下再调用本地 `/api/terrains`，本地服务不可用时只给出提示，不会丢失已读取的公开地形。
- 目录去重使用解析后的完整 URL。相同 URL 的公开条目优先，避免本地服务重复展示同一数据。
- `VITE_LOCAL_SERVICE_URL` 可覆盖开发者本地服务地址；默认值仍为 `http://127.0.0.1:8765`，但生产构建在未显式开启本地工具时不会使用它。

### Vercel 部署说明

- Vercel 使用 `npm run build:vercel`，输出目录为 `site-dist`。构建产物包括页面 bundle、Cesium `Assets`、`Workers`、`Widgets`、`ThirdParty` 静态资源和 `terrain/catalog.json`。
- `tools`、测试、库 `dist` 和本地缓存不会作为网站部署文件上传；`example/public/terrain` 不在忽略范围内，会随网站发布。
- `VITE_CESIUM_ION_TOKEN` 是浏览器可见 Token，必须在 Cesium ion 后台限制 Vercel 预览域名、生产域名和本地域名。私密服务端密钥不能使用 `VITE_*`。
- 大型地形不建议放入 Vercel Deployment，需要单独评估对象存储、CDN、CORS、缓存、下载体积和带宽成本。

### 用户使用方法

- 公开用户打开网站后无需 ion Token 即可看到 OpenStreetMap 和示例风场。
- 在“地形”模式刷新或打开目录，可选择网站已经发布的 quantized-mesh 地形；目录为空时页面会明确说明暂无已发布数据。
- 开发者运行 `npm run dev` 和 `npm run local:server` 后，可继续使用本地风场目录、NetCDF 转换、DEM 转换和 `tools/terrain-output` 地形，并在发布前进行检查。
- 开发者完成 DEM 转换后，需要把小型结果复制到 `example/public/terrain` 或把大型结果上传到对象存储/CDN，再更新 `catalog.json`。

### 兼容性与影响范围

- `TerrainController`、风场图层 API、本地 Python 服务接口和现有 npm 库构建保持兼容。
- 原 `serviceTokens.js` 不再被示例入口读取。已有本地配置需要迁移到 `example/.env.local` 的 `VITE_CESIUM_ION_TOKEN`。
- 公开生产页面的工具按钮会禁用，这是对原来“看似可用但实际请求访客 localhost”行为的有意修正；开发模式下操作方式不变。
- 没有 Cesium ion Token 时默认底图从 Cesium 影像改为 OpenStreetMap；配置 Token 后仍优先使用 Cesium 影像。
- 地图右下角现在会显示 Cesium 和数据提供者署名，属于公开底图合规所需的可见变化。

## 2026-10-12：修正地形加载失败后的稳定状态恢复

### 更新背景

- `TerrainController` 会保存最后一次成功加载的地形状态，以便新地形初始化失败时继续显示原有地形。
- 原实现允许瓦片进度和瓦片错误事件在地形加载失败提示期间覆盖这份稳定状态，连续失败时可能把上一次失败提示、待加载瓦片数量或错误计数带入下一次回退结果。

### 修改内容与实现说明

- 调整 `src/terrain/TerrainController.js`，只有控制器处于 `ready` 状态时，瓦片进度和运行时瓦片错误才会更新最后成功地形快照。
- 加载失败时仍会向界面报告本次错误，但不会把失败态写入稳定快照；下一次加载继续失败时，状态会从最后一次真正成功的地形恢复。
- 新增连续失败回归测试，覆盖“成功加载本地地形、第一次加载失败、旧地形继续产生进度和错误事件、第二次加载再次失败”的完整顺序。

### Vercel 部署说明

- 本次只修改浏览器端地形状态管理，不新增 API、环境变量、路由、外部存储或本地进程依赖。
- 代码继续随 Vite 静态构建发布，Vercel 部署方式不受影响。

### 用户使用方法与兼容性

- 用户操作方式没有变化，仍可在“场景”中切换世界地形，在“地形”中加载本地或公开 quantized-mesh 数据。
- 新地形加载失败时，当前已经显示的正常地形会继续保留；连续尝试损坏或不可访问的数据源也不会污染后续状态。
- `TerrainController` 的公开方法和状态字段保持兼容，没有不兼容接口变更。

### 验证过程与结果

- 已执行 `npm test -- --run tests/terrain/TerrainController.test.js`。
- 地形控制器测试文件共 6 项测试，全部通过。
- Vercel 实际线上部署验证：未执行。本次不涉及部署配置；完整生产构建和页面检查将在本轮地形功能全部修改完成后统一执行。

### 已知限制与后续事项

- 本次只处理状态快照边界，没有改变地形数据来源。当前示例的本地目录发现和 DEM 转换仍依赖开发者本机服务，后续批次将单独处理公开网站与本地工具的功能边界。

## 2026-10-12：确立 Vercel 公开部署与更新文档规范

### 更新背景

- 项目后续将通过 Vercel 部署为可供其他用户访问的网站，开发判断不能再只以本机运行成功为标准。
- 项目包含 Python、Docker、本地目录和本地服务等开发工具，需要明确区分线上网站功能与开发者离线工具，避免普通用户在 Vercel 网站上看到无法实际使用的功能。
- 为保证后续修改容易理解和追踪，项目需要统一每次更新后的文档内容与质量要求。

### 修改内容

- 新增根目录 `AGENTS.md`，将 Vercel 部署、公开用户使用、安全、兼容性和文档维护要求设为整个项目的长期开发约束。
- 新增 `docs/开发与更新规范.md`，用更详细的方式说明前端、服务端、数据处理、环境变量和更新日志的编写要求。
- 更新 `docs/README.md`，把新的开发规范加入项目文档索引。
- 明确以后每次代码、配置、页面、接口、数据流程或部署方式修改后，都必须同步更新 `docs/更新日志.md`；复杂更新还要新增专题文档。

### Vercel 部署原则

- 面向用户的功能必须能够在 Vercel 生产环境中使用，不能依赖开发者电脑的绝对路径、`localhost` 接口或长期运行的本地进程。
- API 和资源地址优先使用同源相对路径，以兼容 Vercel 预览域名和正式域名。
- 需要持久保存的上传文件、转换结果和大型数据不能只依赖 Vercel 函数的临时文件系统，应使用适合的线上存储或数据服务。
- Python、Docker 和本地服务仍可用于开发和离线数据预处理，但必须明确其使用边界，并把网站所需结果发布到线上可访问的位置。
- 私密密钥必须通过环境变量管理，不能进入前端代码、仓库或文档。

### 更新文档要求

- 每次记录需要说明更新背景、修改内容、实现方式、Vercel 部署影响、使用方法、兼容性、验证结果、已知限制和相关文件。

## 1. 安装 Docker Desktop

在 Windows 上安装完整的 **Docker Desktop**，不要只安装 Docker 命令行工具。

安装时建议选择：

- 使用 **WSL 2 backend**
- 启用 Windows Subsystem for Linux
- 启用 Virtual Machine Platform

如果电脑没有 WSL 2，可以用管理员 PowerShell 执行：

```powershell
wsl --install
```

然后重启电脑。

启动 Windows 后，打开 Docker Desktop，等待界面显示 Docker 已经运行。Docker Desktop 必须保持打开，后续脚本才能调用 Docker。

## 2. 检查 Docker 是否可用

打开 PowerShell，执行：

```powershell
docker --version
```

正常情况下会看到类似：

```text
Docker version 27.x.x
```

然后执行：

```powershell
docker info
```

如果 Docker 正常运行，会显示服务器、容器、镜像等信息。

如果出现下面这类错误：

```text
error during connect
Cannot connect to the Docker daemon
```

说明 Docker Desktop 没有启动完成。需要先打开 Docker Desktop，并等待它完全启动后再执行命令。

注意：仅仅看到 `docker --version` 有输出还不够，必须确保 `docker info` 也能够正常执行，因为真正进行 DEM 转换的是 Docker daemon。

列表中应该能看到：

如果下载失败，常见原因包括：

- Docker Desktop 没有启动
- 网络无法访问 Docker Hub
- 公司网络或校园网络设置了代理
- Docker Desktop 的代理没有配置正确
- 磁盘空间不足

可以先测试 Docker 是否能运行普通容器：

```powershell
docker run --rm hello-world
```

如果 `hello-world` 也运行失败，说明 Docker 本身还没有配置好，不是项目脚本的问题。

## 10. DEM 文件准备要求

为了提高成功率，建议注意以下事项：

- DEM 最好是单个文件。
- DEM 应该带有正确的坐标参考系 CRS。
- 如果没有 CRS，脚本可能无法正确判断地理位置。
- 数据最好是 GeoTIFF 格式，即 `.tif` 或 `.tiff`。
- 多个 DEM 瓦片需要先拼接，或者逐个处理。
- DEM 范围越大、分辨率越高，处理时间越长。
- 文件路径尽量使用英文、数字和下划线，避免特殊符号。
- 输出目录所在磁盘需要有足够空间。
- Docker Desktop 需要保持运行到处理完成。
