## 2026-10-25：安装 shpjs、接入浏览器 Shapefile 并完成真实样本验收

### 更新背景

- 前一阶段工具页已经支持 GeoJSON/TopoJSON，但 Shapefile 因依赖安装审批被阻断而暂缓。
- 用户明确授权在授权环境执行 `npm install shpjs@6.2.0 --save`，因此本次继续完成浏览器本地 Shapefile 解析和现有矢量图层接入。

### 修改内容与实现

- 在 `package.json` 和 `package-lock.json` 增加生产依赖 `shpjs@6.2.0`。该 package 使用 MIT License；本项目只调用其公开 ESM API，不复制第三方源码。
- 扩展 `example/services/vectorFileLoader.js`：支持单个 Shapefile ZIP，也支持同时选择同名 `.shp/.dbf/.prj/.cpg` 配套文件；结果统一转换为 GeoJSON FeatureCollection，再交给 Cesium `GeoJsonDataSource`。
- 扩展 `example/app/sceneToolsController.js`：将浏览器 `FileList` 复制为普通数组后再清空文件输入，保留 Shapefile 文件名和要素数量，并继续登记到右侧“矢量数据”组。复制顺序保证用户可以重复选择同名文件。
- 更新 `example/index.html` 文件选择器，允许 `.zip`、`.shp`、`.dbf`、`.prj`、`.cpg`、`.shx` 和 JSON 文件；界面明确提示 Shapefile ZIP 与配套文件选择方式。
- 增加 Shapefile ZIP、配套文件组、缺少 `.shp` 文件的单元测试，并同步更新服务层 README、示例 README、功能专题文档、项目结构索引和文件功能索引。

### Vercel、依赖与兼容性

- Shapefile 解析完全发生在浏览器，用户文件不会上传到 Vercel、本机 Python 服务或第三方服务。
- `shpjs` 及其 `but-unzip`、`parsedbf`、`proj4` 依赖会进入生产构建依赖图；需要通过生产构建检查 bundle 体积和 Vercel 安装流程。
- 本次支持的推荐格式是包含完整配套文件的 Shapefile ZIP。单独 `.dbf`、`.prj` 或 `.shx` 不能独立解析；缺少 `.dbf` 可能没有属性字段，缺少 `.prj` 时无法根据投影信息转换。
- 现有 50 MiB 文件总大小和 100,000 个要素限制继续适用于 Shapefile，防止浏览器解析时占用过多内存；不代表接近上限的数据在所有设备上都能流畅运行。

### 验证过程与结果

- 已在授权环境成功执行 `npm install shpjs@6.2.0 --save`，`npm ls shpjs --depth=0` 显示 `shpjs@6.2.0`。
- `node --check` 对新增加载器和控制器通过；完整 `npm test` 通过（17 个测试文件、85 项测试）。修复 FileList 生命周期后，场景工具定向测试为 6 项通过；`npm run build:vercel` 通过，最终入口 bundle 约 303.95 kB、gzip 97.81 kB。
- 使用用户提供的 `D:\下载\内蒙古自治区` 原始文件组做真实解析：`.shp/.shx/.dbf/.prj/.cpg` 均被读取，`.prj` 为 WGS84，经 `shpjs` 得到 12 个 Polygon 要素，坐标范围约为经度 97.172763～126.068359、纬度 37.406779～53.337178，属性字段包含 `adcode`、`name`、`level` 等。
- 在授权启动的 Vite 浏览器预览中导入同一组文件的临时副本，页面显示“Shapefile · 12 个要素 · 仅保留在当前浏览器”，右侧“矢量数据”组登记图层，并显示隐藏、定位、移除动作。浏览器测试不上传文件。

### 已知限制与后续事项

- 当前不会自动扫描本机目录，也不会从 `.shp` 文件旁边隐式读取未选择的 `.dbf/.prj` 文件；用户需要选择 ZIP 或同时选择配套文件。
- 本次样本是 WGS84 Polygon 行政区数据；其他编码、投影定义、复杂 MultiPolygon、超大属性表和接近 50 MiB 的大文件仍需额外样本验证。
- Vercel Preview/Production 尚未验证；本地生产构建通过后仍需线上检查实际安装、bundle 下载和公开网站运行状态。

## 2026-10-25：工具页新增点位、模型路线、坐标拾取与 GeoJSON/TopoJSON

### 更新背景

- 用户希望在“工具”折叠页创建和命名地图点位、绘制可供模型移动的路线、加载矢量文件并点击位置读取坐标。
- 参考示例 `08 飞行漫游.html` 是相机漫游示例而不是模型漫游；当前网站没有可直接复用的模型文件。因此首版改为访客在浏览器选择单文件 `.glb`，与绘制路线绑定。
- 原方案考虑直接浏览器解析 Shapefile ZIP，但 npm registry 在当前环境不可用且安装权限被拒绝。用户确认缩小本轮范围：先做点位、模型路线、坐标拾取和 GeoJSON/TopoJSON，不增加依赖；Shapefile 暂不支持。

### 修改内容与实现

- 在 `example/index.html` 的空“工具”页增加互斥地图模式、点位名称编辑、路线绘制/命名、模型选择与播放控制、坐标结果和 GeoJSON/TopoJSON 文件入口。
- 新增 `example/app/sceneToolsController.js` 负责 Cesium 点击处理、点和路线 Entity、GLB `ModelGraphics`、路线时间采样、速度朝向、状态控件和统一图层注册。路径支持结束或取消；GLB 以临时 Blob URL 加载，播放前保存 Viewer Clock 状态，并在结束/停止/移除时恢复。
- 新增 `example/services/vectorFileLoader.js` 在浏览器本地解析 JSON，限制 50 MiB 和 100,000 要素。GeoJSON 使用 Cesium 原生 `GeoJsonDataSource`；TopoJSON 通过本项目小型转换器处理仿射变换、delta 编码、共享弧线和反向弧线引用，再转换成 GeoJSON。
- 点位、路线和 GeoJSON/TopoJSON 资源进入既有 `SceneLayerRegistry` 的“矢量数据”分组，复用右侧显隐、定位和移除控制；页面卸载时移除 Entity/DataSource、解除监听并撤销 Blob URL。
- 新增 `tests/example/sceneToolsController.test.js` 与 `tests/example/vectorFileLoader.test.js`，覆盖坐标格式、地形拾取回退、路线速度采样、GeoJSON/TopoJSON 变换/弧线连接和输入限制。
- 新增专题文档 `docs/工具页地图标注与路线.md`，并更新示例网站、业务层、服务层 README 以及项目文档索引。

### 技术选择、部署与兼容性

- 复用 Cesium `ScreenSpaceEventHandler`、`ModelGraphics`、`SampledPositionProperty`、`VelocityOrientationProperty`、`GeoJsonDataSource` 和项目现有图层注册，不修改核心风场库，不访问 Cesium 私有属性。
- 未新增依赖、许可证负担或第三方浏览器代码；TopoJSON 转换依据其公开格式规范实现。Shapefile ZIP、KML、外部依赖 `.gltf`、多文件模型、服务器上传、导出和跨会话保存不在本次范围。
- 生产网站仍是 Vite 静态站点，无新增 Serverless Function、路由、环境变量或服务。用户选择的矢量/GLB 文件通过浏览器本地 API 和临时 Object URL 读取，不会上传到 Vercel、本机 Python 服务或第三方。
- `.glb` 限制 100 MiB；GeoJSON/TopoJSON 限制 50 MiB、最多 100,000 个要素。接近限制时的实际体验取决于访客设备、模型复杂度和 WebGL 能力。数据仅存在当前浏览器会话，刷新或关闭页面后清除。
- 点位名称和路线属于新的临时场景数据，不改变已有公共 API、风场数据格式或公开 URL。右侧图层列表现在会在“矢量数据”组显示这些资源。

### 用户使用方法

1. 打开顶部“工具”，选择“创建点”后点击地图；连续落点，或选中已有点后编辑名称并保存。
2. 选择“绘制路线”，按顺序点击至少两个位置，结束路线并命名；选择路线和单文件 GLB，设定米/秒速度后播放、暂停、继续或停止。
3. 选择“点击获取坐标”后点击地图；结果显示 WGS84 经度、纬度、高度和拾取来源。
4. 选择 GeoJSON 或 TopoJSON 文件加载；成功后在右侧“矢量数据”组显隐、定位或移除。Shapefile 目前需要维护者离线转换为支持的格式。

### 已知限制与风险

- 模型要求一个自包含 `.glb` 文件；依赖外部文件的 `.gltf` 不支持。模型文件过大、资源引用异常、WebGL 不支持或设备内存不足时，Cesium 可能无法显示；实际失败提示与真实 GLB 仍须浏览器检查。
- 路径按相邻点的三维直线距离和固定速度采样，使用线性插值；不会自动贴地重采样、沿道路约束、避障或做曲线平滑。方向由 Cesium `VelocityOrientationProperty` 推导，资产自身前向轴可能影响视觉朝向。
- 播放使用 Viewer 全局 Clock。本次入口未见其他时间动画，但与以后新增的时间轴功能并用时需要重新检查互相影响。
- TopoJSON 转换覆盖常见点、线、面、多几何与 GeometryCollection；不同数据生产软件的扩展字段、非标准结构和极端复杂拓扑仍需要真实样本验证。
- Shapefile 解析器、许可证、构建包体和 Vite 集成尚未复核/验证，待环境允许依赖安装并重新确认后再实现。
- 本地 Vercel 等价生产构建和代表性桌面浏览器交互已验证；Vercel Preview/Production 线上域名未验证。真实 GLB 渲染/播放和矢量导入尚未在浏览器验收，自动测试不能替代这些 Cesium/WebGL 与 File API 检查。

### 错误与更正记录

- 最初工具页方案将 Shapefile ZIP 解析列入方案一；npm registry 无缓存且依赖安装审批拒绝。错误/异常并非代码测试失败，随后没有绕过审批，而是经用户确认将本轮缩小为无需新依赖的 GeoJSON/TopoJSON 支持；Shapefile 作为遗留待办，不宣称已支持。
- 定向测试首次执行遇到沙箱 `spawn EPERM`。更正方式是按授权流程在允许启动子进程的环境运行相同测试，结果 8 项通过；环境限制仍可能影响未授权的其他构建/浏览器命令。
- 浏览器验收中发现并更正 GLB 初始位置属性未保存、列表重绘沿用旧选中项的问题；添加单测后最终定向测试 10 项通过，最终生产构建通过。测试代码最初的 DOM 替身缺少 `querySelector`，补足替身后通过，没有因此修改生产 DOM 代码。矢量 File API、GLB WebGL 实际绘制和播放周期仍未验证。Vercel 线上部署未执行。本次未发现其他需要纠正的错误。

## 2026-10-22：新增 WRF-ARW 多层风场离线转换方法

### 更新背景

- 用户提供的 `wrfout_d01_2024-04-03_08-00-00(1).nc` 不能直接由现有网页 NetCDF-3 加载器读取。WRF 文件是 NetCDF-4/HDF5，且其 U/V/W 错列、二维曲线经纬度和地形跟随垂直层不符合通用 `convert_netcdf.py` 的一维坐标、同形数组假设。
- 将 WRF 变量名简单映射到通用转换器会产生错误风向或高度，不能作为可靠修复。本次新增独立离线转换器，明确执行 WRF 诊断、统一高度和规则网格处理。

### 修改内容与实现

- 新增 `tools/netcdf/convert_wrf.py`，使用 `wrf-python` 的 `uvmet`、`wa`、`z` 诊断量：水平风被去错列并旋转为地理东/北分量，垂直风和高度落到质量网格后再进行下一步插值。
- 每个源网格柱分别垂直插值到覆盖全域的共同 MSL 高度层，默认间距 500 米；然后用 SciPy 对 WRF 二维曲线经纬网做线性三角剖分，生成规则的一维 `lon`、`lat` 网格。
- 凸包外或在任一高度/分量上无效的目标点不填零，转换器裁出最大的完整有效矩形，输出 NetCDF-3 64-bit offset，维度为 `U/V/W(lev,lat,lon)`。
- 新增 `tests/tools/test_convert_wrf.py` 覆盖共同高度范围、逐列垂直插值、越界遮罩、最大有效矩形和高度单调性。
- 新增 `docs/WRF风场离线处理方法.md`，记录安装、命令、参数、算法、浏览器核验和 Vercel 发布边界；同步更新 NetCDF 工具 README、tools、tests 和项目文档索引。

### 技术调研与方案选择

- 查阅 NCAR WRF Users Guide 的 Arakawa C 网格说明，以及 `wrf-python` 的 `getvar`/`interplevel` 官方 API。采用 `uvmet`/`wa`/`z`，避免手写并可能误实现网格去错列、投影旋转和位势高度处理。
- SciPy 仅作为离线可选转换环境依赖，用其成熟 Delaunay/线性插值实现二维曲线到规则经纬网重采样；没有把 `wrf-python`、SciPy 或 NetCDF 依赖添加到网站/npm 包，也未复制第三方实现代码。`wrf-python` 为 Apache-2.0，SciPy 为 BSD-3-Clause；项目只调用 API，不分发其源码或二进制。
- 依据 conda-forge 包文件列表和 NCAR Windows 构建 issue，推荐 Linux/WSL2 使用 `wrf-python 1.4.2`；截至 2026-10-22 原生 win-64 仍只列较旧 `1.3.4.1`，因此 Windows 原生兼容性未验证。官方资料：`https://www2.mmm.ucar.edu/wrf/site/documentation/users_guide/dynamics.html`、`https://wrf-python.readthedocs.io/en/latest/user_api/generated/wrf.getvar.html`、`https://wrf-python.readthedocs.io/en/latest/user_api/generated/wrf.interplevel.html`、`https://github.com/NCAR/wrf-python/issues/307`。

### Vercel 部署、兼容性与用户使用

- 本次只新增本地 Python 离线维护工具和文档，没有改浏览器加载器、npm 依赖、Vercel 路由、公开接口、环境变量或静态资源；Vercel 构建产物不包含该转换工具，也不会自动发布 `tools/converted/` 数据。

## 2026-10-21：公开网站在浏览器内加载本地 GeoTIFF 地形

### 更新背景

- 原“选择并处理 DEM”会把文件提交到 `127.0.0.1:8765`，由 Python、Docker、GDAL 和 CTB 生成 quantized-mesh。该流程适合开发者离线制作发布数据，但公开 Vercel 访客无法启动开发者电脑上的服务。
- 本地服务上传接口还存在请求体大小边界，用户此前只能在不开启 `npm run local:server` 时处理非常小的数据，无法直接验证 7.1 MB 和 58.1 MB 的真实西峰山东侧 GeoTIFF。
- 用户提供了 `D:\AAAcode\CesiumLearn\Cesium-learn\Cesium-Learn\libs\Terrain` 下的两份原始 DEM 与两份对应 quantized-mesh 结果，要求网页端不依赖本地服务即可加载原始数据，并在成功后正确定位到 DEM 范围。

### 修改内容

- 新增 `example/services/browserDemTerrain.worker.js`，在模块 Web Worker 内读取 GeoTIFF、识别坐标系、重投影、扫描高程并按 Cesium 瓦片请求采样 heightmap。
- 新增 `example/services/demRasterMath.js`，集中实现 EPSG:4326 与 WGS84 UTM 南北半球识别、`proj4` 转换、Cesium 全球瓦片范围、最大层级推导、NoData 判断和双线性插值。
- 新增 `example/services/browserDemTerrain.js`，管理 Worker 请求、取消和释放，并使用 Cesium 公共 `TerrainProvider` 与 `HeightmapTerrainData` 接口提供当前会话地形。
- `TerrainController` 新增 `loadProvider()`，让调用方创建的 Provider 继续复用现有地形异步竞态、状态、瓦片错误、进度和相机定位逻辑；同步增加 `TerrainProviderEntry` TypeScript 声明。
- 地形页入口改为“选择并加载 DEM”。公开网站和开发环境选择 `.tif`/`.tiff` 时都优先走浏览器 Worker；`.img`、`.asc`、`.dem` 或需要持久化 quantized-mesh 时，在开发环境继续使用旧本地服务。
- 增加 DEM 处理进度与取消按钮。应用公开地形、目录地形、本地 quantized-mesh 文件夹、世界地形、椭球或另一个 GeoTIFF 时，会终止旧 Worker 并释放栅格引用。
- 竞争地形操作在开始时会先取消仍在解析的 GeoTIFF；一旦浏览器 Provider 已成功应用，则保留到新地形成功接管后再释放，既防止旧 DEM 晚到覆盖用户新选择，也避免新地形失败时提前破坏当前可用地形。
- 公开模式不再因为打开工具区域而探测 `127.0.0.1:8765`。NetCDF 转换继续明确属于开发者离线工具，不受本次 DEM 优化影响。
- 新增示例站点开发依赖 `geotiff@3.0.5` 和 `proj4@2.22.0`，并将 `package-lock.json` 纳入版本管理，不再通过 `.gitignore` 忽略依赖锁文件；两者不作为 npm 核心库运行依赖发布给纯库消费者。
- 为 Vite 开发站点和 Vercel 站点增加 `worker: { format: "es" }`，使 GeoTIFF 压缩解码器可以在 Worker 中按格式 code-splitting。
- 新增 `docs/浏览器本地DEM加载.md`，并同步更新示例、服务、UI、地形、类型、测试、离线工具、Vercel 部署、项目结构和文件索引文档。

### 实现说明

- Worker 使用 `geotiff` 读取第一个栅格波段、`GeoKeys`、NoData、原点、分辨率和源范围。浏览器模式只接受 EPSG:4326、EPSG:32601-32660 与 EPSG:32701-32760；其他投影不猜测参数，而是提示先用离线 GDAL 转换。
- WGS84 UTM 数据通过 `proj4` 把源范围转换为经纬度，并在每个 Cesium 采样点把经纬度反投影到源像元。EPSG:4326 数据直接使用原坐标，不进行无意义转换。
- 自定义 Provider 使用 Cesium `GeographicTilingScheme` 的全球 `2 x 1` 零级瓦片和北向南 Y 编号，避免把局部四叉树编号误当成 Cesium 全球瓦片路径。
- 每个请求生成 `65 x 65` `Float32Array`，并由 `HeightmapTerrainData` 交给 Cesium。Worker 保存最多 96 个瓦片的 LRU 缓存，减少相机轻微移动时的重复采样。
- 最大层级根据源栅格经纬度分辨率推导，上限限制为 22。数据范围外只保留到 10 级的 0 m 瓦片，之后用 `getTileDataAvailable()` 和 `childTileMask` 停止细分，兼顾全球场景可见性和无数据区域开销。
- NoData 邻点不参与双线性权重；四个邻点都无效或采样超出栅格时返回 0 m，避免把 `-32767`、`-9999` 渲染成深坑。
- 原始 `File` 只发送给当前页面创建的同源 Worker，不经过 Vercel Function、本地 Python 服务或第三方。处理结果只在当前标签页内存中存在，不生成或下载 `.terrain`。

### 技术调研与依赖选择

- 采用 Cesium 官方公共 `TerrainProvider`、`HeightmapTerrainData` 和 `GeographicTilingScheme`，没有访问下划线私有属性、修改 Cesium 构建产物或复制 Cesium 内部实现。
- `geotiff@3.0.5` 来源为 `geotiffjs/geotiff.js`，MIT 许可证，用于浏览器 GeoTIFF 解码。选择原因是其覆盖 TIFF 元数据、GeoKeys、NoData 与多种压缩解码，并可在模块 Worker 中运行。
- `proj4@2.22.0` 来源为 `proj4js/proj4js`，MIT 许可证，只用于 WGS84 与 WGS84 UTM 南北半球分区互转，避免自行实现投影公式。
- 两项依赖版本均在 `package.json` 和 `package-lock.json` 精确锁定；`npm audit --json` 报告 0 个已知漏洞。
- 曾评估浏览器 WASM 直接生成 quantized-mesh 的方案。代表性 GeoTIFF 验证发现候选实现返回错误范围、未识别真实 NoData，并使用局部四叉树而非 Cesium 全球 `GeographicTilingScheme` 编号，因此未采用，也没有复制其代码。

### Vercel 部署说明

- 公开站点新增的是纯浏览器能力，不新增 Serverless Function、上传接口、密钥、固定域名或本地端口依赖。
- GeoTIFF 不进入 HTTP 请求体，因此不再受旧本地上传接口约 4.5 MB 的请求体边界影响，也不占用 Vercel Function 执行时间、临时磁盘和上传带宽。
- `npm run build:vercel` 已通过，共转换 2000 个模块。主站脚本约 `244.46 kB`，浏览器 DEM Worker 入口约 `177.75 kB`；JPEG、Deflate、LZW、PackBits、LERC 与 Zstd 解码器保持独立 chunk。
- Vercel Preview 和生产域名：未验证。本次只完成与 Vercel 等价的本地生产构建和生产预览，线上域名、CDN 缓存与实际访客设备内存仍有剩余风险。

### 用户使用方法

1. 打开工作台并进入“地形”。
2. 点击“选择并加载 DEM”，选择 `.tif` 或 `.tiff`。
3. 等待页面显示 CRS、高程范围和“文件未上传”；需要中止时点击“取消本次 DEM 处理”。
4. 成功后页面自动飞到 DEM 范围，也可以再次点击“定位当前地形”。
5. 刷新页面后需要重新选择文件。需要把地形分享给其他用户或长期发布时，仍使用 `tools/terrain/build_quantized_mesh.py` 生成 quantized-mesh 并发布到静态目录或对象存储。

### 兼容性与影响范围

- 公开 GeoTIFF 支持范围为 EPSG:4326、WGS84 UTM 北半球 1-60 区和南半球 1-60 区。CGCS2000、高斯-克吕格和其他 CRS 会给出明确提示，不会尝试错误定位。
- `.img`、`.asc`、`.dem` 和 persistent quantized-mesh 生成保持原开发者流程，已有 `npm run local:server`、Python/Docker 工具与已处理地形目录仍可使用。
- `TerrainController.loadProvider()` 是向后兼容新增；现有 `loadLocal()`、`loadWorld()`、`useEllipsoid()` 和公开类型没有删除或改名。
- 页面没有设置新的固定文件大小上限。可处理规模取决于浏览器可用内存、栅格尺寸和压缩格式，不能把 58.1 MB 的成功结果理解为所有更大文件都必然可用。
- 浏览器 DEM 与本地 quantized-mesh 文件夹使用不同会话实现：前者在 Worker 中动态采样，后者通过 Service Worker 提供原有 `.terrain` 文件；两者不会互相覆盖资源所有权。

### 错误与更正记录

- 初始方案曾尝试浏览器 WASM quantized-mesh 编码。真实数据证明其范围、NoData 和瓦片编号不适合当前项目后，改为 Cesium 公共 heightmap Provider，避免输出位置错误的伪 quantized-mesh。
- UTM 单元测试最初使用了未经真实投影结果核对的期望范围。更正方法是从 GeoTIFF 元数据读取 EPSG:32650 源范围，使用 `proj4` 转换后与对应 WGS84 数据交叉核对，再更新期望值。
- 首次 Vercel 构建失败，原因是 Vite 默认把 Worker 输出为 IIFE，而 `geotiff` 解码器需要多 chunk。更正为 `worker: { format: "es" }` 后构建通过。
- 首次 JavaScript 全量测试在沙箱内因 esbuild `spawn EPERM` 失败；首次 Python 测试因系统临时目录权限失败。两者在获准的沙箱外环境重跑后分别为 58 项和 12 项全部通过，确认不是代码回归。
- UTM 浏览器自动化在文件选择后的等待阶段超时，但页面继续完成处理。重新连接标签页后核对成功状态、地形名称和相机高度，确认超时来自自动化等待而不是应用失败。
- WGS84 浏览器检查读取不存在的 `.status-bar` 选择器时超时；页面实际状态已经成功。更正为读取可访问性树和截图中的 `.app-statusbar` 可见内容，确认地形与相机状态。
- 依赖初次加入时放在 `dependencies`。复核发现它们只由 `example/` 使用，若保留会让纯 npm 库消费者安装无关 GeoTIFF 解码代码；更正为 `devDependencies`，随后重新生成 lockfile，并用库构建和 Vercel 站点构建分别验证两个发布边界。
- 最终源码审阅发现，解析中的 GeoTIFF 与目录/世界/椭球地形操作可能并发，旧解析结果存在晚到后覆盖用户最后选择的风险。更正为竞争操作开始即中止待处理 Worker，并在 Provider 成功应用后立即结束“待处理”状态；结合 Worker 取消测试和 `TerrainController` 既有竞态测试重新验证。

### 已知限制与后续事项

- NoData 全无有效邻点时回退 0 m，可能在 DEM 有效边缘形成可见过渡。对展示质量要求较高的数据应离线填洞、裁切或生成 quantized-mesh。

- 当前不生成法线、水面遮罩或持久化缓存，刷新后需要重新选择文件。
- 浏览器只读取第一个波段，没有提供多波段选择 UI；输入文件应把目标高程放在第一波段。
- Vercel Preview、生产域名、低内存设备和更多 GeoTIFF 压缩/投影样本尚未验证。

## 2026-10-20：恢复近景粒子线长并完善渲染参数控件

### 更新背景

- 上一轮为了消除全球视角的放射状长线，把 `lineLength` 改成纯像素上限。该处理虽然不再拉长远景粒子，但也让近景只显示很短的单帧真实位移，导致单个粒子过小。
- 因为多数真实投影线段远短于配置上限，“最大线长”控件只具备截短作用，拖动时几乎看不出变化。
- 原“流动速度”使用 `0.01～5` 的线性滑块，低速范围集中在极短的左侧行程，无法继续降低到 `0.01` 以下，也不方便细调。

### 修改内容

- `src/shaders/segmentDraw.js` 恢复区域近景的目标像素线长，并仅在三维相机拉远时把人为延长平滑衰减到真实投影长度。
- 远景衰减约从相机高度 `1500 km` 开始，到 `5000 km` 完全使用真实投影长度；使用平滑曲线避免缩放过程突然跳变。
- “最大线长”控件与实际默认值统一为 `80 px`，范围统一为 `20～240 px`、步进 `5 px`，解决页面显示 `400` 但图层实际使用 `80` 的状态不一致。
- “流动速度”使用低速端更精细的比例滑块，实际 `speedFactor` 范围调整为 `0.05～5`，默认值保持 `0.3`；数值填写框步进为 `0.01`。
- 六项渲染参数均增加原生 `number` 填写框，分别声明最小值、最大值和步进。滑块负责快速调整，填写框负责精确输入，两者通过同一个提交函数同步，不各自维护状态。
- 每项参数名称右侧增加“默认值”标记；“渲染参数”标题右侧增加“恢复默认”按钮，一次恢复六项数值参数，但保留“按风速加密”和“动画”开关状态。
- 新增 `example/app/windControlScale.js` 隔离速度滑块换算和通用数值校验，并新增 `tests/example/windControlScale.test.js` 覆盖低速范围、默认值回填、边界限制、步进对齐和空值回退。

### 实现说明

- Shader 先计算 `current → next` 的真实投影像素长度。近景的目标长度仍按风速在 `lineLength.min/max` 之间插值，因此“最大线长”会直接改变高速粒子的可见长度。
- 三维相机高度通过 `czm_viewerPositionWC` 到地心距离减去 WGS84 长半轴近似得到。该值只用于视觉衰减，不参与风场数据坐标或粒子物理推进。
- 衰减权重从近景的 `1` 平滑下降到全球远景的 `0`：权重为 `1` 时使用目标像素长度，权重为 `0` 时使用真实投影长度。二维模式不应用相机高度衰减。
- 速度滑块内部使用 `0～200` 的比例位置映射到 `0.05～5`，但填写框和 `WindLayer2D/WindLayer3D` 始终使用普通浮点 `speedFactor`，没有改变库接口。
- 滑块触发 `input` 时立即更新参数和填写框；填写框允许用户完整键入，只在 `change` 时按 HTML 中的 `min/max/step` 校正并同步滑块，避免两个输入入口互相争抢未完成的输入。
- 恢复默认时先更新六项控件和 `sharedOptions`，再以一个选项对象更新每个图层，避免六次连续更新可能造成的闪烁和额外资源重建。
- 方案参考 MDN 对原生 `range`、`number` 和 `step` 的说明，以及 WAI-ARIA Slider Pattern 对范围值、键盘操作、可访问名称和 `aria-valuetext` 的要求。项目未引入第三方控件库，而是使用浏览器原生表单控件和现有业务状态实现最小方案。

## 2026-10-20：修复全球视角下流线被固定像素长度拉长

### 更新背景

- 2026 年 10 月 14 日的流线修复解决了近景中线长乘相机尺度后直接进入裁剪空间导致的全屏爆射，但用户在继续缩小到全球视角时发现，局部风场又呈现从中心向外发散的长线。
- 截图表明风场覆盖区域已经缩成地球上的小块，而每条流线仍保持明显的屏幕像素长度，说明问题不再来自 NetCDF 异常条带，而是上一版 Shader 将配置线长解释为“强制目标长度”。

### 修改内容

- 将 `src/shaders/segmentDraw.js` 中的 `extendInScreenPixels()` 替换为 `clampSegmentToPixelLimit()`。
- `lineLength.min/max` 现在明确表示按风速插值后的“最大屏幕像素长度”，不再表示每条线必须达到的目标长度。
- Shader 根据 `current` 和 `next` 粒子位置计算真实投影像素长度；真实长度小于上限时保留真实终点，超过上限时才沿原方向截短。
- 新增 `tests/shaders/segmentDraw.test.js`，检查 Shader 使用 `min(1.0, 上限/真实长度)`，并继续保留零长度和零速度范围保护。
- 新增 `tests/shaders/README.md`，更新 `tests/README.md`、`src/shaders/README.md`、中英文根 README 和 `docs/Wind3D异常诊断与修复.md`，说明线长上限语义、测试范围和远近相机验证要求。

### 实现说明

- 在透视除法后，`current → next` 的 NDC 差值先按视口高宽比修正，再乘视口高度的一半得到真实屏幕像素长度。
- 缩放系数使用 `min(1.0, pixelLimit / actualPixelLength)`。当真实长度小于上限时系数为 `1`，终点就是真实的 `next`；只有真实长度超过上限时，系数才小于 `1` 并截短线段。
- 受限后的 X/Y 在 NDC 中插值，深度也按相同比例插值后还原到裁剪空间，避免只改屏幕位置却保留不一致深度。
- `lineLength` 仍按速度从 `min` 插值到 `max`，因此高速线段可以拥有更大的允许上限，但不会在远景中被无条件延长。

### Vercel 部署说明

- 本次只修改随 Vite 打包的 GLSL 字符串、测试和文档，没有新增 API、环境变量、Serverless Function、本地绝对路径或生产环境 `localhost` 依赖。

### 实现说明

- “选择并处理 NC”只负责把原始 NetCDF 交给开发者本机 Python 服务转换；转换完成后，风场数据的加载和渲染仍在同一个“风场”页继续操作。
- “选择并处理 DEM”只负责通过开发者本地服务和 Docker CTB 生成 quantized-mesh；处理结果可以通过下方“加载本地文件夹”立即检查，也可以发布到公开地形目录或对象存储。
- “加载本地文件夹”调用浏览器文件夹选择器，检查 `layer.json` 和 `.terrain` 瓦片，并通过 Service Worker 的同源虚拟 URL 交给 Cesium。文件只在当前浏览器会话中读取，不会上传到 Vercel、项目服务器或第三方服务。
- “刷新地形目录”重新读取随网站发布的目录，并在开发环境合并本地服务目录；“选择目录地形”使用弹窗浏览目录；“应用所选地形”加载当前下拉框选中的 URL。三个按钮处理的是目录数据，不会扫描电脑任意文件夹。
- 新增 `syncTerrainActions()`：当地形下拉框没有有效 URL 时禁用“应用所选地形”；“定位当前地形”继续由地形状态订阅逻辑控制，只在当前本地地形存在有效 `bounds` 时启用。
- 目录刷新会重建下拉框。为避免刷新后丢失仍在使用的浏览器本地地形选项，`refreshTerrains()` 会重新插入当前 `localTerrainSession`，再尝试恢复刷新前的选中项。
- 释放浏览器本地地形会话时同步移除对应选项并更新按钮状态，避免页面仍显示可应用但 URL 已失效的地形。
- `local-terrain-sw.js` 增加关键中文注释，说明会话只保存规范化路径、只拦截 `/__local-terrain__/`、Service Worker 重启后向页面取回 `File`，以及 gzip 瓦片的解压兼容逻辑。

## 2026-10-12：修正地形加载失败后的稳定状态恢复

- 调整 `src/terrain/TerrainController.js`，只有控制器处于 `ready` 状态时，瓦片进度和运行时瓦片错误才会更新最后成功地形快照。

- 新增连续失败回归测试，覆盖“成功加载本地地形、第一次加载失败、旧地形继续产生进度和错误事件、第二次加载再次失败”的完整顺序。

## 1. 安装 Docker Desktop

在 Windows 上安装完整的 **Docker Desktop**，不要只安装 Docker 命令行工具。

安装时建议选择：

- 使用 **WSL 2 backend**
- 启用 Windows Subsystem for Linux
- 启用 Virtual Machine Platform

如果电脑没有 WSL 2，可以用管理员 PowerShell 执行：

```powershell
wsl --install
```

然后重启电脑。

启动 Windows 后，打开 Docker Desktop，等待界面显示 Docker 已经运行。Docker Desktop 必须保持打开，后续脚本才能调用 Docker。

## 2. 检查 Docker 是否可用

打开 PowerShell，执行：

```powershell
docker --version
```

正常情况下会看到类似：

```text
Docker version 27.x.x
```

然后执行：

```powershell
docker info
```

如果 Docker 正常运行，会显示服务器、容器、镜像等信息。

如果出现下面这类错误：

```text
error during connect
Cannot connect to the Docker daemon
```

说明 Docker Desktop 没有启动完成。需要先打开 Docker Desktop，并等待它完全启动后再执行命令。

注意：仅仅看到 `docker --version` 有输出还不够，必须确保 `docker info` 也能够正常执行，因为真正进行 DEM 转换的是 Docker daemon。

## 3. 拉取 DEM 转换镜像

第一次使用前，在 PowerShell 中执行：

```powershell
docker pull tumgis/ctb-quantized-mesh:latest
```

这个命令会下载项目默认使用的镜像。

下载完成后，可以用下面的命令检查镜像是否存在：

```powershell
docker images
```

列表中应该能看到：

```text
tumgis/ctb-quantized-mesh
```

如果下载失败，常见原因包括：

- Docker Desktop 没有启动
- 网络无法访问 Docker Hub
- 公司网络或校园网络设置了代理
- Docker Desktop 的代理没有配置正确
- 磁盘空间不足

可以先测试 Docker 是否能运行普通容器：

```powershell
docker run --rm hello-world
```

如果 `hello-world` 也运行失败，说明 Docker 本身还没有配置好，不是项目脚本的问题。

## 4. 启动项目的本地服务

进入项目目录：

```powershell
cd "D:\AAAcode\CesiumLearn\Cesium-learn\Cesium-Learn\OtherPeopleS\cesium-wind-layer-3d"
```

启动本地服务：

```powershell
npm run local:server
```

正常情况下会启动：

```text
http://127.0.0.1:8765
```

这个服务主要负责：

## 10. DEM 文件准备要求

为了提高成功率，建议注意以下事项：

- DEM 最好是单个文件。
- DEM 应该带有正确的坐标参考系 CRS。
- 如果没有 CRS，脚本可能无法正确判断地理位置。
- 数据最好是 GeoTIFF 格式，即 `.tif` 或 `.tiff`。
- 多个 DEM 瓦片需要先拼接，或者逐个处理。
- DEM 范围越大、分辨率越高，处理时间越长。
- 文件路径尽量使用英文、数字和下划线，避免特殊符号。
- 输出目录所在磁盘需要有足够空间。
- Docker Desktop 需要保持运行到处理完成。

## 11. 常见错误

### 错误一：找不到 Docker

如果看到：

```text
docker command not found
```

或者：

```text
无法将“docker”项识别为 cmdlet
```

说明 Docker Desktop 没有安装，或者 Docker 没有加入 PATH。

解决方法：

1. 安装 Docker Desktop。
2. 重启 PowerShell。
3. 再执行：

```powershell
docker --version
```

### 错误二：Docker daemon 未运行

如果看到：

```text
Cannot connect to the Docker daemon
```

解决方法：

1. 打开 Docker Desktop。
2. 等待状态变为 Running。
3. 执行：

```powershell
docker info
```

### 错误三：镜像下载失败

执行：

```powershell
docker pull tumgis/ctb-quantized-mesh:latest
```

如果失败，可以检查：

```powershell
docker run --rm hello-world
```

如果网络问题持续存在，需要在 Docker Desktop 的设置中配置代理，或者换用可以访问 Docker Hub 的网络环境。

### 错误四：提示缺少 `layer.json`

这通常说明转换过程没有完整执行，可能原因包括：

- 输入 DEM 无法读取
- DEM 坐标系缺失或错误
- Docker 镜像执行失败
- CTB 工具处理失败
- 磁盘空间不足
- DEM 文件损坏

需要查看运行 `npm run local:server` 的 PowerShell 窗口，里面会有具体错误日志。

### 错误五：网页能打开，但地形加载失败

检查以下内容：

```powershell
npm run local:server
```

是否仍在运行。

然后访问：

```text
http://127.0.0.1:8765/health
```

如果返回健康状态，说明本地服务正常。

还需要确认：

```text
tools/terrain-output/<名称>/layer.json
```

确实存在，并且浏览器访问的是：

```text
http://localhost:3000/
```

而不是直接双击 HTML 文件。
