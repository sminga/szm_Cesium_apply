## 2026-10-20：恢复近景粒子线长并增加低速精细调节

### 更新背景

- 上一轮为了消除全球视角的放射状长线，把 `lineLength` 改成纯像素上限。该处理虽然不再拉长远景粒子，但也让近景只显示很短的单帧真实位移，导致单个粒子过小。
- 因为多数真实投影线段远短于配置上限，“最大线长”控件只具备截短作用，拖动时几乎看不出变化。
- 原“流动速度”使用 `0.01～5` 的线性滑块，低速范围集中在极短的左侧行程，无法继续降低到 `0.01` 以下，也不方便细调。

### 修改内容

- `src/shaders/segmentDraw.js` 恢复区域近景的目标像素线长，并仅在三维相机拉远时把人为延长平滑衰减到真实投影长度。
- 远景衰减约从相机高度 `1500 km` 开始，到 `5000 km` 完全使用真实投影长度；使用平滑曲线避免缩放过程突然跳变。
- “最大线长”控件与实际默认值统一为 `80 px`，范围统一为 `20～240 px`、步进 `5 px`，解决页面显示 `400` 但图层实际使用 `80` 的状态不一致。
- “流动速度”改为对数滑块，实际 `speedFactor` 范围扩展为 `0.001～5`，默认值保持 `0.3`。低速值显示两到三位小数，方便观察和精细调节。
- 新增 `example/app/windControlScale.js` 隔离滑块换算逻辑，并新增 `tests/example/windControlScale.test.js` 覆盖低速范围、默认值回填、上限和显示精度。

### 实现说明

- Shader 先计算 `current → next` 的真实投影像素长度。近景的目标长度仍按风速在 `lineLength.min/max` 之间插值，因此“最大线长”会直接改变高速粒子的可见长度。
- 三维相机高度通过 `czm_viewerPositionWC` 到地心距离减去 WGS84 长半轴近似得到。该值只用于视觉衰减，不参与风场数据坐标或粒子物理推进。
- 衰减权重从近景的 `1` 平滑下降到全球远景的 `0`：权重为 `1` 时使用目标像素长度，权重为 `0` 时使用真实投影长度。二维模式不应用相机高度衰减。
- 速度滑块内部位置按以 10 为底的对数换算，但 `WindLayer2D/WindLayer3D` 继续接收原有普通浮点 `speedFactor`，没有改变库接口。

### Vercel 部署说明

- 本次只修改浏览器端 Shader、静态页面控件、纯 JavaScript 换算模块、测试和文档，没有新增 Serverless Function、环境变量、固定域名、本地路径或生产环境本地服务依赖。
- 新模块会随 Vite 打包进入公开站点；控件和 Shader 在 Vercel 与本地使用同一实现。
- Vercel 实际预览/生产域名仍需检查不同屏幕、DPR 和 GPU 下的远近景过渡效果。

### 用户使用方法与兼容性

- “最大线长”默认显示 `80`。区域近景拖动到 `20～240` 时应能明显改变粒子长度；拉远到全球视角后会自动缩短以避免放射变形。
- “流动速度”仍默认 `0.3`。向左可逐级降低到 `0.001`，低速区间占用更多滑块行程；向右仍可提高到约 `5`。
- `lineLength` 和 `speedFactor` 的公共配置结构、类型和调用方法均保持兼容。行为变化只涉及远景线长衰减和示例页面的控件刻度。

### 错误与更正记录

- 极低速度会让粒子移动非常缓慢，这是控件允许精细观察轨迹的预期结果，不代表动画停止。
- 相机高度使用椭球半径近似值，对本用途足够，但不是测地学高程计算。

## 2026-10-20：修复局部 DEM 的“定位当前地形”跳转到全球范围

### 更新背景

- 用户通过“加载本地文件夹”选择 `tools/terrain-output/xfsDEMWGS84` 后，地形本身可以加载，但点击“定位当前地形”不能跳转到该 DEM 的实际区域。
- 检查该目录的 `layer.json` 后确认：标准 `bounds` 是 `[-180, -90, 180, 90]`，表示全球瓦片金字塔范围；真实 DEM 范围保存在 `valid_bounds`，约为东经 `116.0336-116.0532`、北纬 `40.1532-40.1646`。
- 原浏览器文件夹检查器和开发者本地目录扫描器都只读取 `bounds`，因此把全球范围交给 `TerrainController.flyToCurrentTerrain()`，相机只能保持或飞回全球视角。

### 修改内容

- 修改 `example/services/localTerrainFolderLoader.js` 的定位范围解析：优先采用合法的 `valid_bounds`，缺失或无效时回退到 `bounds`。
- 修改 `tools/terrain/terrain_dataset.py`，让开发环境“刷新地形目录”返回与浏览器文件夹入口一致的定位范围，并在 `valid_bounds` 无效时记录警告。
- 修复“应用所选地形”按钮直接把 `click Event` 传给 `loadSelectedTerrain()` 的现有问题；按钮现在显式无参数调用，让函数按下拉框 URL 查找真实地形条目。
- 补充经纬度合法范围检查，拒绝超出经度 `[-180, 180]` 或纬度 `[-90, 90]` 的定位元数据。
- 新增 JavaScript 和 Python 回归测试，使用 `xfsDEMWGS84` 的“全球 `bounds` + 局部 `valid_bounds`”结构验证定位优先级，并验证无效 `valid_bounds` 对旧 `bounds` 的兼容回退。
- 更新地形服务、本地工具、测试和 Vercel 公开地形文档，解释 `bounds` 与 `valid_bounds` 的用途差异。

### 实现说明

- `layer.json` 仍原样交给 `CesiumTerrainProvider`，瓦片模板、层级、可用性和 Service Worker 请求路径均未修改。
- 页面单独提取用于相机定位的矩形：先校验 `valid_bounds` 是否为四个有限数字、是否符合 `[west, south, east, north]` 顺序以及合法经纬度范围；有效时使用它，否则继续检查 `bounds`。
- `TerrainController` 和 `Rectangle.fromDegrees()` 不需要修改。根因位于传入控制器之前的元数据选择，而不是相机飞行 API。
- 开发者本地 Python 服务复用 `terrain_dataset.py` 的检查结果，因此从目录下拉框加载同一数据集时也会得到真实 DEM 范围，避免两个入口行为不一致。
- “应用所选地形”的函数仍支持目录弹窗显式传入地形对象；只有普通按钮事件改为包装函数，避免把 DOM Event 与业务对象混淆。

### Vercel 部署说明

- 本次修改的浏览器解析逻辑会随 Vite 进入 Vercel 站点，支持访客主动选择其电脑上的处理结果；文件仍只保留在当前浏览器会话，不会上传到 Vercel 或第三方服务。
- Python 目录扫描仅属于开发者本地服务，公开网站不会依赖 Python、Docker、固定盘符、`127.0.0.1` 或该示例数据路径。
- 没有新增环境变量、Serverless Function、路由或静态大文件，也没有把 `xfsDEMWGS84` 打入 Vercel 构建产物。
- 已完成 Vercel 使用的 `npm run build:vercel` 生产构建；实际 Vercel 预览/生产域名仍未验证，本地构建和本地浏览器结果不替代线上结论。

### 用户使用方法

1. 在“地形”页点击“加载本地文件夹”。
2. 选择包含 `layer.json` 和 `.terrain` 瓦片的 `xfsDEMWGS84` 文件夹。
3. 等待页面显示“本地地形已加载”后，点击“定位当前地形”。
4. 页面应飞到 `valid_bounds` 描述的北京局部区域，而不是停留在全球视角。

### 兼容性与影响范围

- 已有只提供 `bounds` 的本地文件夹和目录地形继续按原行为定位。
- 同时提供两个字段时，`valid_bounds` 的优先级提高；这是对 CTB 局部 DEM 语义的修正，不改变公开 `TerrainController.loadLocal()` 的参数格式。
- 公开 `catalog.json` 条目仍使用自己的 `bounds` 字段，不会额外请求远端 `layer.json`；大型公开地形的对象存储、CDN、CORS、缓存和带宽要求不变。
- 风场数据、Shader、粒子渲染、Cesium ion 图层、基础影像和 DEM 转换命令均不受影响。
- “应用所选地形”从原本点击后报“缺少本地地形 URL”恢复为按下拉框选中项加载；目录弹窗调用方式保持兼容。

## 2026-10-20：修复全球视角下流线被固定像素长度拉长

### 更新背景

- 2026 年 10 月 14 日的流线修复解决了近景中线长乘相机尺度后直接进入裁剪空间导致的全屏爆射，但用户在继续缩小到全球视角时发现，局部风场又呈现从中心向外发散的长线。
- 截图表明风场覆盖区域已经缩成地球上的小块，而每条流线仍保持明显的屏幕像素长度，说明问题不再来自 NetCDF 异常条带，而是上一版 Shader 将配置线长解释为“强制目标长度”。

### 修改内容

- 将 `src/shaders/segmentDraw.js` 中的 `extendInScreenPixels()` 替换为 `clampSegmentToPixelLimit()`。
- `lineLength.min/max` 现在明确表示按风速插值后的“最大屏幕像素长度”，不再表示每条线必须达到的目标长度。
- Shader 根据 `current` 和 `next` 粒子位置计算真实投影像素长度；真实长度小于上限时保留真实终点，超过上限时才沿原方向截短。
- 新增 `tests/shaders/segmentDraw.test.js`，检查 Shader 使用 `min(1.0, 上限/真实长度)`，并继续保留零长度和零速度范围保护。
- 新增 `tests/shaders/README.md`，更新 `tests/README.md`、`src/shaders/README.md`、中英文根 README 和 `docs/Wind3D异常诊断与修复.md`，说明线长上限语义、测试范围和远近相机验证要求。

### 实现说明

- 在透视除法后，`current → next` 的 NDC 差值先按视口高宽比修正，再乘视口高度的一半得到真实屏幕像素长度。
- 缩放系数使用 `min(1.0, pixelLimit / actualPixelLength)`。当真实长度小于上限时系数为 `1`，终点就是真实的 `next`；只有真实长度超过上限时，系数才小于 `1` 并截短线段。
- 受限后的 X/Y 在 NDC 中插值，深度也按相同比例插值后还原到裁剪空间，避免只改屏幕位置却保留不一致深度。
- `lineLength` 仍按速度从 `min` 插值到 `max`，因此高速线段可以拥有更大的允许上限，但不会在远景中被无条件延长。

### Vercel 部署说明

- 本次只修改随 Vite 打包的 GLSL 字符串、测试和文档，没有新增 API、环境变量、Serverless Function、本地绝对路径或生产环境 `localhost` 依赖。
- 修改后的 Shader 会随 `npm run build:vercel` 进入公开站点 JavaScript bundle，Vercel 路由和静态资源托管方式不变。
- 实际 Vercel 预览/生产域名仍需验证不同设备 GPU、浏览器 WebGL2 实现和真实视口下的视觉表现；本地生产构建不能替代线上验证。

### 用户使用方法

- 用户继续通过“最大线长（像素）”滑块设置允许的最大屏幕长度，操作入口和数值范围没有变化。
- 相机在区域近景时，过长线段会被限制在配置上限内；相机拉远到全球视角时，真实投影不足上限的线段会自然缩短。
- 如果仍觉得远景过密，可以降低粒子密度或关闭按风速加密；不再需要仅为避免放射线而把最大线长降到极小值。

### 兼容性与影响范围

- `lineLength` 的对象结构、类型声明和调用方式保持兼容，仍使用 `{ min, max }`。
- 行为语义从“强制像素长度”更正为“像素长度上限”。依赖上一版固定屏幕长度视觉效果的调用方会看到远景线段变短，这是本次有意修复。
- NetCDF 转换、异常纬度条带修复、粒子推进速度、颜色、宽度、高度选择和二维/三维图层 API 均未改变。

## 1. 安装 Docker Desktop

在 Windows 上安装完整的 **Docker Desktop**，不要只安装 Docker 命令行工具。

安装时建议选择：

- 使用 **WSL 2 backend**
- 启用 Windows Subsystem for Linux
- 启用 Virtual Machine Platform

如果电脑没有 WSL 2，可以用管理员 PowerShell 执行：

```powershell
wsl --install
```

然后重启电脑。

启动 Windows 后，打开 Docker Desktop，等待界面显示 Docker 已经运行。Docker Desktop 必须保持打开，后续脚本才能调用 Docker。

## 2. 检查 Docker 是否可用

打开 PowerShell，执行：

```powershell
docker --version
```

正常情况下会看到类似：

```text
Docker version 27.x.x
```

然后执行：

```powershell
docker info
```

如果 Docker 正常运行，会显示服务器、容器、镜像等信息。

如果出现下面这类错误：

```text
error during connect
Cannot connect to the Docker daemon
```

说明 Docker Desktop 没有启动完成。需要先打开 Docker Desktop，并等待它完全启动后再执行命令。

注意：仅仅看到 `docker --version` 有输出还不够，必须确保 `docker info` 也能够正常执行，因为真正进行 DEM 转换的是 Docker daemon。

```powershell
docker images
```

列表中应该能看到：

```text

```

如果下载失败，常见原因包括：

- Docker Desktop 没有启动
- 网络无法访问 Docker Hub
- 公司网络或校园网络设置了代理
- Docker Desktop 的代理没有配置正确
- 磁盘空间不足

可以先测试 Docker 是否能运行普通容器：

```powershell
docker run --rm hello-world
```

如果 `hello-world` 也运行失败，说明 Docker 本身还没有配置好，不是项目脚本的问题。

## 10. DEM 文件准备要求

为了提高成功率，建议注意以下事项：

- DEM 最好是单个文件。
- DEM 应该带有正确的坐标参考系 CRS。
- 如果没有 CRS，脚本可能无法正确判断地理位置。
- 数据最好是 GeoTIFF 格式，即 `.tif` 或 `.tiff`。
- 多个 DEM 瓦片需要先拼接，或者逐个处理。
- DEM 范围越大、分辨率越高，处理时间越长。
- 文件路径尽量使用英文、数字和下划线，避免特殊符号。
- 输出目录所在磁盘需要有足够空间。
- Docker Desktop 需要保持运行到处理完成。
