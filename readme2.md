# Cesium 三维风场可视化项目介绍

## 一、项目概述

这是一个基于 CesiumJS 的三维风场可视化项目。简单来说，我把气象数据中的风速和风向转换成了地图上可以直接观察的动态流线：粒子会随着风场方向不断运动，颜色和密度还会随着风速变化。

项目的目标不是只显示一张静态风速图，而是让使用者能够在三维地球上直观看到“风从哪里来、往哪里吹、不同高度的风有什么差异”。整个项目可以作为气象数据展示、论文演示和三维地理信息系统可视化的基础。

## 二、我主要完成了什么

本项目在原有三维风场图层的基础上，补充和完善了数据加载、风场表达以及交互控制功能，主要成果包括：

1. **实现三维风场动态显示**
   - 使用经向风速 `u`、纬向风速 `v` 和垂直风速 `w` 三个分量描述风场。
   - 粒子在经度、纬度和高度三个方向上运动，因此显示的是三维风场，而不是只有平面方向的二维风场。
   - 粒子计算主要交给 GPU 完成，可以减少 CPU 的计算压力，使风场能够连续动画显示。

2. **加入风速颜色表达**
   - 使用连续色带表示风速大小。
   - 低速区域通常使用蓝色、青色，高速区域逐渐过渡到黄色、橙色和红色。
   - 页面中提供风速图例，用户可以根据颜色大致判断风速范围。

3. **让低速风场也更容易观察**
   - 原来低速区域的流线比较暗，容易被地图背景遮住。
   - 我增加了低速流线的最低透明度，并调整了颜色和线宽，使低速区域仍然具有较好的可见性。
   - GUI 中增加了“低速显眼度”滑块，可以根据背景和展示效果进行调整。

4. **让高速区域的粒子更加密集**
   - 普通随机播种会导致粒子在整个区域分布比较平均，难以突出高速风区。
   - 项目加入了速度加权粒子播种方法：风速越大的位置，获得的粒子越多；低速区域仍然保留一定数量的粒子。
   - 这样可以在不完全牺牲整体风场连续性的情况下，更直观地突出高速风区。

5. **支持本地 NetCDF 数据加载**
   - GUI 可以选择本地 NetCDF-3 文件，并在加载后重建风场图层。
   - 加载器可以识别常见的经度、纬度、高度以及 `U/V/W` 变量名称，并自动整理网格顺序。
   - 如果原始文件没有垂直风速 `W`，程序会自动用 0 填充，从而仍然可以显示水平风场。

6. **提供 NetCDF-4 转换工具**
   - 浏览器端使用的加载器主要面向 NetCDF-3 格式。
   - 对于 NetCDF-4/HDF5 文件，我编写了 Python 转换脚本，将常见气象变量整理成项目需要的标准结构并保存为 NetCDF-3。
   - GUI 的“工具”页面可以选择文件并调用本地 Python 服务，处理成功后会显示输出文件的完整保存路径。

7. **整合 Cesium 图层控制**
   - 将风场、底图和三维叠加图层统一放入一个控制面板。
   - 可以在 Cesium 影像、OpenStreetMap 和无底图之间切换。
   - 可以打开或关闭 OSM 建筑物和 Cesium World Terrain，用于观察风场与城市建筑、地形之间的关系。

## 三、项目是怎样工作的

整个流程可以概括为下面几步：

```text
气象数据文件
    ↓
读取 U、V、W 和经纬度、高度网格
    ↓
整理为统一的三维数组
    ↓
计算风速大小和颜色范围
    ↓
把风场数据上传到 WebGL2 三维纹理
    ↓
GPU 计算粒子位置和运动方向
    ↓
在 Cesium 地球上绘制动态流线
```

其中，`U` 表示东西方向的风速，`V` 表示南北方向的风速，`W` 表示垂直方向的风速。每个网格点都有一个三维风速向量，粒子根据所在位置的风速向量不断更新位置。

项目使用三维纹理保存风场数据。这样做的好处是，GPU 可以直接在三维网格中进行插值，粒子经过网格之间的位置时不会出现明显跳变，风场动画看起来更加连续。

## 四、GUI 界面说明

当前示例页面将功能分成三个页面：

### 1. 风场

“风场”页面用于观察和调节风场本身，主要包括：

- 打开本地 NetCDF-3 文件。
- 查看当前数据的网格大小。
- 查看风速颜色图例。
- 调节粒子数量、流动速度、高度拉伸和最大线长。
- 调节低速风场显眼度。
- 开启或关闭按风速加密。
- 开启或关闭粒子动画。

### 2. 图层

“图层”页面用于控制地图和三维场景：

- Cesium 影像底图。
- OpenStreetMap 底图。
- 无底图模式。
- OSM 建筑物。
- Cesium World Terrain 世界地形。

这些按钮可以帮助我在论文汇报时快速切换不同场景，展示风场与真实地理环境的叠加效果。

### 3. 工具

“工具”页面用于处理不能直接加载的 NetCDF 文件：

1. 先运行本地转换服务。
2. 点击“选择并转换 NC”。
3. 选择需要处理的 `.nc` 文件。
4. 等待 Python 脚本完成转换。
5. 页面显示“转换成功”和转换后文件的保存位置。

启动转换服务的命令如下：

```powershell
npm run local:server
```

转换后的文件默认保存到：

```text
tools/converted/
```

## 五、如何运行项目

### 1. 安装依赖

在项目目录中执行：

```powershell
npm install
```

### 2. 配置 Cesium ion

示例页面使用的服务凭据集中放在：

```text
example/config/serviceTokens.js
```

这个文件被加入了 `.gitignore`，不会被提交到代码仓库。项目中还提供了不包含真实密钥的模板：

```text
example/config/serviceTokens.example.js
```

### 3. 启动示例页面

```powershell
npm run dev
```

然后在浏览器访问 Vite 输出的本地地址，例如：

```text
http://127.0.0.1:3001/
```

### 4. 启动 NetCDF 转换服务

如果需要在网页中转换 NetCDF-4 文件，另开一个终端执行：

```powershell
npm run local:server
```

Python 转换脚本需要安装常用科学计算库，例如：

```powershell
py -m pip install xarray numpy netCDF4
```

## 六、项目目录的作用

```text
src/
  核心风场图层、粒子系统、GPU 计算和着色器代码

src/data/
  NetCDF-3 数据读取和格式整理

  NetCDF 读取和按风速进行粒子加权播种

src/shaders/
  GPU 中用于计算速度、粒子位置和流线绘制的着色器

example/
  Cesium 示例页面、GUI 控件、样式和本地数据

tools/
  NetCDF 转换脚本和本地 HTTP 转换服务

tests/
  NetCDF 加载、工具函数和粒子播种相关测试

types/
  TypeScript 类型声明
```

## 七、项目效果和验证结果

通过这个项目，我实现了从气象数据到三维地图动态效果的完整流程。最终页面可以看到不同高度上的风场粒子运动，颜色可以反映风速差异，高速区域的粒子更加密集，低速区域也不会完全消失。

项目还完成了以下验证：

- NetCDF-3 文件可以在浏览器中直接加载。
- NetCDF-4 文件可以通过 Python 工具转换。
- 缺少 `W` 分量的数据可以正常处理。
- 新文件加载后会重建风场图层。
- 底图、建筑物和世界地形可以通过 GUI 切换。
- 单元测试全部通过，生产构建可以正常完成。
- 在窄屏设备上控制面板不会产生横向溢出。

## 八、目前的限制

为了保证浏览器运行稳定，目前项目还有一些使用限制：

- 浏览器直接加载的主要是 NetCDF-3，NetCDF-4/HDF5 需要先转换。
- 数据中的高度坐标需要是米制高度，压力层数据需要提前完成物理转换。
- 文件过大时会占用较多浏览器内存，实际使用时应控制数据规模。
- 项目依赖 WebGL2 和浮点纹理扩展，较老的浏览器或显卡可能无法正常运行。
- Cesium ion 图层需要有效的 Cesium ion token 和网络连接。

## 九、总结

这个项目的核心成果，是把原本不容易直接理解的三维气象风场数据，转化成了可以在三维地球上实时观察的动态粒子流线。通过颜色、线宽、透明度和粒子密度，用户可以更快地判断风速大小和风场分布。

从论文汇报的角度看，我完成的不只是一个显示页面，还包括数据读取、格式转换、GPU 计算、可视化表达和交互控制等多个环节。后续还可以继续加入时间序列播放、风场剖面分析、风速统计和更多气象要素显示，使系统更接近实际的气象分析工具。
